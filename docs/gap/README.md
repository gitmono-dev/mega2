# 竞品差距分析（Gap）

本目录存放 mega2 的**竞品差距分析**文档：以某个外部项目为参照系，分析 mega2 的能力缺口、应坚守的边界与应拒绝的方向。

## 与其它文档目录的关系

| 目录 | 职责 | 与本目录的边界 |
|---|---|---|
| `docs/plan/` | 路线图与可执行任务卡（`plan-long.md` 的 `PT-*` + 日期计划） | **唯一的排期入口。** 本目录只产出候选与依据，不排期、不占用 `PT-*` 编号 |
| `docs/refactoring/` | 内部改进方案（contract / config / vault / mail / notification 等） | 面向**已确定要做**的内部重构；本目录面向**是否要做**的外部对照 |
| `docs/manuel/` | 面向使用者的说明 | 无重叠 |

**移植 vs 对照**：`plan-long.md` 的长期目标是「把 Mega 项目的 Rust 后端能力完整移植到 mega2」，Mega 是**移植来源与契约基线，不是竞品**。本目录的参照对象是 Mega 之外的外部项目；凡本目录提出的、超出 Mega 移植范围的方向，必须在文档内**显式标注为「Mega 之外的新方向」**并说明为什么值得偏离，不得伪装成移植项。

## 规则

1. **只分析，不排期。** 本目录的文档产出的是**候选与依据**。任何条目进入路线图都必须按 `plan-long.md` §路线图维护 的规则重新立项，并给出竞品 revision/path、mega2 缺口、价值、风险、依赖与最小切入点。
2. **不占用 `PT-*` 编号空间。** 每份文档使用自己的内部编号（如 `delta.md` 的 `ME-A*`/`ME-B*`/`ME-C*`），编号一经引用不重编；被推翻的条目改标注为「已实现 / 已替代 / 不采纳」并保留理由，不删除。
3. **事实基线优先。** 每份文档必须以当前 checkout 的源码、测试与文档为事实基线，并在开头的「事实校准」中记录 mega2 的 `git HEAD`、版本与核对日期；竞品侧必须记录 revision 或版本快照。历史计划、竞品的历史描述只能作为线索。
4. **一手来源留档。** 竞品若有本地 checkout，记录其路径与 revision；若无（闭源/私测），必须在附录列出一手来源清单与抓取日期，并写明后续复核的快照规则，使不持有二手材料的读者也能独立核对。
5. **不与已登记决策冲突。** 提出建议前必须核对 `plan-long.md` 已登记的「不采纳」条目与各日期计划的「非目标」段；冲突时须写成对既有决策的**显式挑战**（走 ADR revisit 流程），不得当作新发现。
6. **对照不等于跟进。** 每份文档都应包含「应坚守 / 不跟进」的一组结论，并给出理由；只列缺口不列边界的对照文档不完整。
7. **文档不宣称实现完成。** 同 `docs/plan/README.md` 规则 6：落地时每个建议都必须先刷新源码锚点，再按任务卡验收。
