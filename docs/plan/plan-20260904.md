# Storage-only trunk 产品 API 写文件计划（2026-09-04）

**模板版本：** v2；依据 [`plan-template.md`](plan-template.md)，核对日期 2026-09-10（文件名按指定保留 `plan-20260904`）。

## 文档职责

本文解决：storage-only / `push_policy=trunk` 形态下，产品 HTTP API **只能读、不能写**文件——`create-entry` / `edit/save` 未挂到 trunk 表面，且服务层经 CL 写路径被 `reject_trunk_cl_write` fail-closed。目标是交付 **push_auth 门控、经 MonoWriteQueue 直落 tip** 的 API 写能力，使写后的文件可被 **`git clone` / `git pull`（fetch）** 取回；并交付 **可继承进 `docker-compose-storage-only.yml` 的 compose 黑盒测试方案**（脚本 + 稳定 case + compose 注释契约），供本计划验收，并可由 `plan-20260906` 后续吸收为附加 case。

本文只规划任务，不宣称实现完成。

### 适用范围

- 路由：`src/api/api_router.rs` trunk/`storage_only_routers`；`src/api/router/preview_router.rs` create-entry / edit/save。
- 服务：`src/ceres/api_service/mono_api_service.rs`（`save_file_edit` / `create_monorepo_entry`）；CL fail-closed 保留在 `src/ceres/code_edit/`。
- 落地：`PushQueueService::enqueue_and_wait`（与 `finalize_trunk_push` 同权威）；鉴权复用 `lookup_push_token` / `token_covers_repo`（`src/contract/git_protocol/mod.rs`，对齐 LFS）。
- 测试：库测 + `tests/` IT；**compose 黑盒**脚本 `scripts/api_write_smoke_storage_only.sh` + `docker-compose-storage-only.yml` 注释/可选 profile 入口。
- 文档：`docs/deploy-trunk.md`；交叉引用 `docs/refactoring/integration.md` / `test-infra.md`。

### 非目标

- 不重开 CL / issue / reviewer / merge UI；不启用 Cedar enforce（trunk 仍 `cedar.enforcement=off`）。
- 不打开 SSH receive-pack；不把 API 写做成 `git push` 的全面替代（多 commit / 复杂 LFS 仍走 Git）。
- 不修改 `scripts/git_protocol_smoke.sh` 的 CL 默认语义；不把 Blake3 产品路径拉进本计划。
- 不以 cargo IT 顶替 compose 黑盒 VER（IT 与 compose 分层；二者都要）。
- 大文件内联 blob 无界写入 → `DEFER-AW-01`（可加体积上限或要求 LFS pointer）。

### 成功定义

- Trunk 表面注册 `POST /api/v1/create-entry` 与 `POST /api/v1/edit/save`；OpenAPI 列出二者且仍排除 `/cl` 等 review 面。
- `push_auth=token` 下无凭据写失败；合法 token + path 覆盖下 tip 前进；**零**新 `mega_cl` / `refs/cl/*`。
- 写后经 Git smart HTTP：`git clone` / `git pull` 可见新文件内容。
- Compose 黑盒脚本存在、可复制、结果经 stdout/tee 取得；compose 文件注释给出继承入口（供 plan-20260906 吸收）。
- 非延后卡 `done`/`complete`；本计划 Codex **PASS**；已索引。

## 已决议设计决策

### ADR-AW-01: Trunk-direct 落地（禁止复开 CL 写）

- **Status:** Accepted
- **Context:** 现有 create/save 经 `find_or_create_cl_for_edit` 造 CL，与 trunk 启动不变量冲突。
- **Decision:** API 写在 `PushPolicy::Trunk` 下：**构造 blob/tree/commit → 持久化对象 → `EnqueueRequest { kind: Push, ref_name: refs/heads/main, … }` → `enqueue_and_wait`**，与 `finalize_trunk_push` 同 tip 权威。响应 `cl_link=null`（或省略）；忽略 review 的 `mode`。CL 入口继续 `reject_trunk_cl_write`。
- **Alternatives considered:** 仅挂路由不改服务 — 拒绝（仍 fail-closed / 造 CL）；新 URL 完全另起 — 可作后续，本计划优先复用既有路径名以降低调用方成本。
- **Consequences:** 必须共享/抽取 lander，禁止旁路改 `mega_refs`。
- **Revisit when:** 需要多文件事务 API 或显式 bulk 端点。

### ADR-AW-02: 写鉴权 = `git.push_auth`（对齐 LFS）

- **Status:** Accepted
- **Decision:** Trunk 写路由强制：`token` → Basic/Bearer 密文经 `lookup_push_token` + `token_covers_repo(path)`；失败 401/403。`none` → 允许无凭据写（与 receive-pack/LFS 同级风险，文档警告）。不启用 Cedar。`requester` = token `name`（`none` 用稳定占位如 `anonymous`）。
- **Alternatives considered:** OAuth/session — 拒绝（storage-only 无 OAuth 路由器）。

### ADR-AW-03: Git 可见性契约

- **Status:** Accepted
- **Decision:** API 写成功后，对**同一 path tip** 的 `git clone` / `git fetch`+`pull` **必须**看到新文件内容（对象在库、ref 已前进）。这是产品正确性门，不是可选。
- **Alternatives considered:** 仅 REST GET 可见 — 拒绝。

### ADR-AW-04: Compose 可继承黑盒方案（强制）

- **Status:** Accepted
- **Decision:**
  1. 新增 `scripts/api_write_smoke_storage_only.sh`（bash；客户端：`curl` + `git`；**禁止 `libra` 作协议/API 测试客户端**）。
  2. 稳定 case 名（附录）：API 写 → Git 读回；无凭据拒绝（token 栈）。
  3. 支持 `MONOENGINE_SMOKE_CASE=<exact>` 单 case；summary 行 + `failed>0` → 非 0；宿主可 `tee` 到 `target/tmp/aw-smoke-*.log`。
  4. **Compose 继承契约：** 在 `docker-compose-storage-only.yml` 的 `git-smoke` 注释块登记可复制 `exec` 命令（与协议 smoke 并列）。`git-smoke` 镜像若缺 `curl`，本卡在 `Dockerfile.git-smoke` 增加 `curl`（保持 pin 策略，仅补包）。
  5. **与 plan-20260906 关系：** 本脚本独立；60906 **不**被本计划改 case 编号。吸收方式：60906 后续可增 SO 卡，VER 调用本脚本 basename + case 名（DEP-AW-OUT-01）。本计划 AW-04 VER **不**依赖 60906 已吸收。
- **Alternatives considered:** 只做 cargo IT — 拒绝（用户强制 compose 可继承黑盒）。

### ADR-AW-05: 路径与 B0

- **Status:** Accepted
- **Decision:** API 写目标 path 遵守队列 B0（含 `path != "/"` 等既有拒绝）；根路径创建若产品需要，须落在允许的子 path（文档写明）。NFF/冲突映射为稳定 HTTP 错误（4xx + 可诊断 body）。
