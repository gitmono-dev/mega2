## 文档职责

把已经就位的 Artifacts 协议栈（`artifacts_router` + `ArtifactService` + `artifact_*` 三表 + 对象存储）挂载到唯一交付形态 **trunk / storage-only** 的 HTTP 面上，写端点复用 `git.push_auth` 门控，读端点与 storage-only 其它只读面一致（匿名可读）。完成后 README 的 Artifacts 特性描述即为事实。

### 适用范围

- `api_router::storage_only_routers_with` 合并 `artifacts_router::routers()`。
- 写端点（`POST /batch`、`POST /commit`、`PUT /objects/{oid}`）在 `git.push_auth` 存在时经 `authorize_trunk_api_write` 门控；review 形态行为不变（仍由 `cedar_guard` 裁决）。
- 单元测试（路由注册、OpenAPI 含 artifacts、写鉴权 401/403/200）与 storage-only 进程级黑盒（token 上传 → commit → 下载回读；无凭据 401）。
- README（中英）按已完成口径表述。

### 非目标

- 不改 Artifacts 协议语义、表结构与 `ArtifactService` 逻辑；不新建 `docs/artifacts-protocol.md`。
- 不挂载 `buck_router`（其会话语义绑定 Draft CL，属 review 形态）。
- 不动 `[artifacts_gc]` 后台任务（已是全形态启动）。
- 不做 artifacts 的 Cedar 策略化（storage-only `cedar.enforcement` 恒为 `off`）。

### 成功定义

- storage-only `service http` 下 `/api/v1/repos/{repo}/artifacts/*` 全组可达；写端点无凭据 401、path 越权 403、合法 token 200；读端点匿名 200。
- review 形态路由与鉴权行为零变化（既有测试不回归）。
- 三门禁全绿：`cargo +nightly fmt --all --check`、`cargo clippy --all-targets --all-features -- -D warnings`、`source .env.test && cargo test --all`。

## 已决议设计决策

### ADR-AR-01: 写鉴权用 handler 内条件门控，不加新 middleware

写 handler 内 `if config.git.push_auth.is_some()` 时调用 `authorize_trunk_api_write`；review（`push_auth=None`）跳过，行为完全交给既有 `cedar_guard`。理由：`push_auth` 显式存在当且仅当 storage-only（启动 fail-closed 保证），无需新增形态标记；改动面最小，review 零回归。

### ADR-AR-02: 授权 path 用 `{repo}` 解码后的 monorepo 路径

`{repo}` 段经 `decode_path_segment` 后补前导 `/` 作为 `token_covers_repo` 的 path（如 `org%2Fproject` → `/org/project`），与 push token 的组件边界前缀语义一致。

### ADR-AR-03: 读端点不鉴权

与 storage-only 既有只读面（tag list、blob/tree 读）一致；对象下载仍要求 manifest 已 commit（`artifact_object_model_for_committed_repo_download`），不放大暴露面。
