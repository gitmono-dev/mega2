## 文档职责

本文解决：mega2 仍保留产品不要的通知出站（website-mail、Slack、站内收件箱、`delivery_mode`、locale）以及不属于本仓的协作 UI（评论改删与 emoji、评审、labels/assignees、CLA）。目标是只留 **generic webhook**（外加无关的 `[storage_events]`），CL 只保留 **创建评论 + 列表**，merge 不再要求评审或 CLA。

本文只规划任务，不宣称实现完成。落地时每个任务都必须先刷新源码锚点，再按任务卡验收。

## 已决议设计决策

实现时若需偏离本节，必须先修改计划并说明原因，不得在代码中静默改语义。

### ADR-RM-01: 本仓永不发起邮件

- **Status:** Accepted
- **Context:** SMTP 已按 ADR-WA-08 退场；残留 `WebsiteMailClient` 仍向 website 内部 API POST。产品改为邮件完全由 megaui 拥有。
- **Decision:** mega2 不调用任何发信 API。RM-02B 起 `deliver_user_notification` 不再进入 `delivery_mode==email` 分支。RM-WM 删除客户端与 `website_mail_*` 键。
- **Alternatives considered:** 保留客户端给 megaui 当 SDK — 拒绝（重复契约、本仓不再编排邮件）。
- **Consequences:** 既有 website-mail IT 删除。认证邮件仍在 megaui，本仓不改。
- **Revisit when:** 产品要求本仓再次编排邮件（默认永不）。

### ADR-RM-02: 删除整条 `delivery_mode` 轴

- **Status:** Accepted
- **Context:** `delivery_mode` 只为在 in-app 与 email 之间分流。两边都拆掉后该轴无意义。
- **Decision:** 删除配置 `default_delivery_mode`、settings 列、偏好 API 字段、`validate_notification_delivery_mode`、`current_default_delivery_mode`。不保留枚举兼容窗。
- **Alternatives considered:** 只留 `in_app` 常量 — 用户拒绝（inbox 也删）。
- **Consequences:** 旧客户端再送 `delivery_mode` → 反序列化忽略或 422（实现选：DTO 无该字段则多余字段默认忽略）。
- **Revisit when:** 需要多种出站模式（应新开计划，不复活本字段）。
