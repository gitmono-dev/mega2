# storage-only Agent Capture 落库计划（2026-09-11）

**模板版本：** v2；依据 [`plan-template.md`](plan-template.md)，核对日期 2026-09-13。

## 文档职责

本文解决「libra 本机两套 Agent Session（外部 hook 捕获与内部 `libra code` JSONL）无法以 storage-only 形态原样落入 monoengine」的缺口。目标是交付：**仅在 `git.storage_only()` 且 `[agent_capture].enabled=true` 时挂载 `/api/v1/agent-capture`**——独立 ingest token、无用户/OAuth/Cedar 前置；Postgres 元数据（`agent_capture_*`）+ `ObjectNamespace::Agent` 字节；服务器事实源为 **raw**；查询 metadata-first，点进 transcript 返回 raw 并写 access_audit。

本文只规划任务，不宣称实现完成。落地时每个任务都必须先刷新源码锚点（GC-01），再按任务卡验收。

**权威规范（唯一）：** ADR、下节「HTTP 契约与数据模型冻结」、任务卡字段、「实施顺序」边集。本文件不含后置覆盖附录。若历史 Review 补丁与任务卡冲突，以任务卡与冻结契约为准。

### 适用范围

- `src/config/`：`[agent_capture]`（`enabled`、`tenant_id`、`deployment_id`、配额缺省、`[[agent_capture.ingest_tokens]]`）、`known_fields`、storage-only 校验门。
- `src/callisto/` + `src/jupiter/migration/`：`agent_capture_*` 表、实体、`migrations()` 登记。

- `src/common/canonical_json.rs`（新，AC-22）：RFC 8785 fingerprint helper，供 event/receipt/HTTP 幂等共用。
- `src/api_model/`（新）+ `src/ceres/agent_capture/`（新）：DTO/错误契约与 ingest token 查找（audience 独立，禁止调用 `lookup_push_token`）。
- `src/api/router/agent_capture_router.rs`（新）+ `src/server/http_server.rs` + `src/api/api_doc.rs`：路由、挂载、OpenAPI。
- `tests/integration_agent_capture.rs`（新）：进程级黑盒。
- 文档：`docs/refactoring/agent-capture.md`（AC-01 创建，各实现卡按节追加，AC-14 索引收口）、`docs/refactoring/README.md`、`docs/refactoring/integration.md`、`docs/plan/README.md`、`plan-long.md` 索引。

### 非目标

- **不在 review 形态**挂载 `/api/v1/agent-capture`（不注册 → 404）。
- **不实现** libra Mega remote 客户端（写集在 libra 仓，DEFER-AC-01）。
- **不默认**上传 FileHistory 每文件 50 版全文（DEFER-AC-02）。
- **不实现**后台 GC 清扫进程（DEFER-AC-04）；本计划只保证 GC **查询**不以年龄为唯一条件。
- **不实现**脱敏视图、`agent_experts` / runtime `agent_sessions`、计费镜像、Cedar、OAuth、`LoginUser`。
- **不把** session 写入既有 `audit_logs`（`target_id: i64`）。
- **不改** Git smart protocol / LFS / OCI；不复用 `git.push_tokens` / `git.anonymous_access`；不改 `ObjectNamespace::Media`。
- **不重放** `refs/libra/traces`；不把两套事件合成一条假因果链。

### 成功定义

- storage-only + `enabled=true` + 有效 ingest token：discovery、session upsert、blob staging/finalize、event/file-op/checkpoint ingest、metadata list、raw transcript GET 可用。
- 无 token → 401；token 不覆盖 path → 404；review 或 `enabled=false` → 整棵 404；未挂载时 OpenAPI 不含 `/api/v1/agent-capture`。
- 仅 redacted、无对应 raw blob → `completeness=incomplete`（`missing_raw`）。
- tracing 不含 prompt/token/tool 原文。
- 全部非延后任务卡 `Lifecycle=done` 且 `Acceptance=complete`；计划级 Codex 对本计划文档为 PASS。

## 已决议设计决策

实现时若需偏离本节，必须先修改计划并说明原因，不得在代码中静默改语义。

### ADR-AC-01: 服务器 PK 叫 `capture_id`；客户 id 只叫 `client_session_id`

- **Status:** Accepted
- **Context:** `server_id` 与 HTTP/主机 server 混淆。libra `{provider}__{provider_session_id}` 只标识本机会话。
- **Decision:** `agent_capture_session.id` 为 `BIGINT GENERATED ALWAYS AS IDENTITY`。对外 JSON 与路径参数一律 **`capture_id`**。libra 复合 id 只出现在 `PUT /repos/{repo}/sessions/{client_session_id}`。子表 FK 列名 `capture_id`。`UNIQUE (deployment_id, tenant_id, repo_id, producer_id, session_kind, client_session_id)`。事件 `UNIQUE (capture_id, event_uid)`。首次 PUT 按自然键事务化：先锁/插入自然键，唯一冲突后重读，再使用已有或新建的 `capture_id`。receipt 不参与首次 capture_id 生成。
- **Alternatives considered:** 客户端 id 当全局 PK——拒绝。UUID v7——可后补。
- **Consequences:** 子资源必须先有 PUT 回包中的 `capture_id`。
- **Revisit when:** 需要跨部署联合主键。

### ADR-AC-02: 对象键由服务器派生；含 tenant；客户端不得指定 final key

- **Status:** Accepted
- **Decision:** `ObjectNamespace::Agent` → `to_string()="agent"`。ObjectKey **path**（不再重复 namespace 段）：staging `{deployment_id}/{tenant_id}/staging/{lease_id}`；committed `{deployment_id}/{tenant_id}/{visibility}/sha256/{hex}`。首版 `visibility=raw` 为事实源。`deployment_id`/`tenant_id` 来自配置。blob 表 `object_key` 只存服务器值。
- **Alternatives considered:** 客户端提交 key / 跨租户单 CAS——拒绝。
- **Consequences:** 同 digest 不同 tenant 是两行两把 key。
- **Revisit when:** 多区域复制。

### ADR-AC-03: 双重门 + 独立 ingest token；不跟随 `anonymous_access`

- **Status:** Accepted
- **Decision:** `[agent_capture].enabled` 缺省 false。挂载 `git.storage_only() && enabled`。`enabled=true` 且非 storage-only → **config validate 拒绝**。启用后所有 discovery/list/show/ingest 要有效 ingest token（无 token **401**）。token 不覆盖正规化 path → **404**。`[[agent_capture.ingest_tokens]]`：`name`、`token`、`paths`（`token_path_authorizes`）、可选 `tenant_id`（若出现必须等于段级值）。查找为独立函数、sha256 常数时间，**禁止**调用 `lookup_push_token`。`producer_id` = token `name`。`enabled=true` 要求至少一条 token。认证头为 `Authorization: Bearer <token>`。
- **Alternatives considered:** 复用 push_tokens / 跟随 anonymous_access——拒绝。
- **Consequences:** 运维必须配置 ingest token 才能启用；跟踪样例配置保持 disabled、无可用 token。
- **Revisit when:** DEFER-AC-03。

### ADR-AC-04: 必须收 raw；独立 access_audit / tombstone；不扩 `audit_logs`

- **Status:** Accepted
- **Decision:** Discovery `raw_accepted=true`。仅 redacted 无 raw → `completeness=incomplete`，`partial_reason=missing_raw`。`GET transcript` 返回 raw 并 INSERT `agent_capture_access_audit`。禁止写入 `audit_logs`。tombstone 命中后再 ingest → 409。tracing 只记 id/digest/size。
- **Alternatives considered:** 拒 raw / 扩 audit_logs——拒绝。
- **Consequences:** 持有 ingest token 即能读 raw。
- **Revisit when:** 法律 hold 产品化。

### ADR-AC-05: `repo_id` = 正规化 mega 路径 TEXT

- **Status:** Accepted
- **Context:** 两台 clone → 两个 `libra.repoid`。monorepo 路径常无 `git_repo` 行。
- **Decision:** `/repos/{repo}` 为**单一 URL segment**，值为 percent-encoded 路径。服务端先解码、再 `normalize_repo_path` 得到 `repo_id` TEXT，再做 token scope。禁止 Axum 中段 catch-all。授权、UNIQUE、隔离都用 `repo_id`。`libra_repoid` 可空 metadata，不作 FK/token/object key。
- **Alternatives considered:** `git_repo.id` FK——拒绝。`{*repo}` catch-all——拒绝。
- **Consequences:** 同一 mega 路径共用 `repo_id`；用 `producer_id` 区分实例。
- **Revisit when:** 真实多租户 org 表。

### ADR-AC-06: blob_ref 是 GC 真相；lease 冻结三元组

- **Status:** Accepted
- **Decision:** `agent_capture_blob_ref` 使用明确 owner 列（session/event/checkpoint/file_op）+ CHECK 恰好一个 owner；与 owner 同行同事务。禁止单独 `ref_count` 当唯一真相。staging 把 lease 写成 token 的 tenant/repo/producer 与 `capture_id`。finalize 路径必须等于 lease；服务器重算 digest。未过期他方 409。GC 查询：`NOT EXISTS blob_ref AND (lease 空或过期) AND state<>protected`。lease 状态 `staging -> finalizing -> committed` 或 `expired/aborted`，条件更新必须包含 owner generation。
- **Alternatives considered:** 只按年龄删——拒绝。多态 `owner_pk`——拒绝。
- **Consequences:** 后台 sweeper 为 DEFER-AC-04。
- **Revisit when:** 周期 GC。

### ADR-AC-07: storage-only 可独立使用；无用户列

- **Status:** Accepted
- **Decision:** 表无 `user_id`。`cl_link` 可空且首版不写不查不当授权。`tenant_id`/`deployment_id` 为配置常数。
- **Alternatives considered:** 等 OAuth——拒绝。
- **Consequences:** review 首版不挂载。
- **Revisit when:** DEFER-AC-03。

### ADR-AC-08: file-op 版本化契约；不从 ToolUse JSON 推断

- **Status:** Accepted
- **Decision:** `agent.file_op.v1`。无 `source_event_uid`（或不存在）则拒绝。`op ∈ {read,write,patch,delete,search}`。路径拒 `..`、NUL、绝对路径。digest 非空必须指向已 finalize raw blob。
- **Alternatives considered:** 从 tool JSON 猜字段——拒绝。
- **Consequences:** 客户端必须显式发 file-op 批。
- **Revisit when:** 需要服务端派生。

### ADR-AC-09: JSONL uid 一律 `{generation}:{byte_offset}`；incomplete 一等

- **Status:** Accepted
- **Decision:** JSONL 去重禁止 UUID/tool_call_id/内容 hash。原生 id 进 `native_id`。lifecycle 用 `lifecycle_seq`。`source_stream (capture_id, stream_kind, generation)`。`completeness ∈ {empty,incomplete,complete,truncated}`。未知 kind 存 envelope。FileHistory 不默认 50 版全文。单 session file blob 缺省上限 20。
- **Alternatives considered:** event_id 当 uid——拒绝。
- **Consequences:** jsonl 重写必须升 generation。
- **Revisit when:** 跨 generation 折叠查询。

### ADR-AC-10: blob staging 以 session 为边界；tenant 固定来自配置

- **Status:** Accepted
- **Decision:** staging/finalize 使用 `/sessions/{capture_id}/blobs/...`，不得使用 repo-level staging。请求不得提交 tenant_id、deployment_id 或 final object key；有效 tenant/deployment 一律来自 `[agent_capture]` 配置。token 的 `tenant_id` 若存在，必须与配置值相同，否则配置拒绝。所有 session、blob、tombstone、audit 查询均带 effective tenant/deployment 条件。
- **Consequences:** tombstone 可在 staging 前以 `capture_id` 检查；同 repo 下不同 session 不会共享未绑定的 lease。

### ADR-AC-11: canonical JSON 与明确的状态/错误契约

- **Status:** Accepted
- **Decision:** 需要比较 payload 的 idempotency key、event UID 与 receipt 均使用 RFC 8785 canonical JSON fingerprint；JSON 欄位顺序不影响相同判定；拒绝 duplicate key、NaN/Infinity 与溢出数字。HTTP 认证与资源判定顺序为 401 → 404 → 409 → 400/413。固定 schema 的未知 session/stream 值拒绝；未知 event kind 存 `unknown` 并保留 envelope。PUT fingerprint 不含服务端 completeness/lifecycle。
- **Consequences:** 所有 batch 为整批事务；同 fingerprint 重试返回既有结果，不同 fingerprint 返回 409。

## HTTP 契约与数据模型冻结

router 内部 path 以 `/agent-capture` 开头，由外层 nest 到 `/api/v1`；下表 public path 为完整外部路径，实现时不得再加一层 `/api/v1`。

认证：`Authorization: Bearer <ingest_token>`。错误响应固定 `{ "error": { "code": string, "message": string } }`，不得包含 token secret、raw prompt、tool 原文或其他 tenant 是否存在的线索。分页统一 `limit` 与 `cursor`，默认 `limit=50`，最大 `limit=200`；list response `{ "items": [...], "next_cursor": string|null }`。
