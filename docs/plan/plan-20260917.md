## 文档职责

本文解决：storage-only / `push_policy=trunk` 的产品 HTTP 能列目录、能建目录，但**不能**删除/移动/改名目录，也**不能**在该形态下列出/创建/删除 monorepo tag。目标是交付与 `create-entry` 同级的目录变更面，并把已存在的 Review `tag_router` 挂到 storage-only，使 Libra `mega2 browser` 的 TUI 键可以消费真实契约而不是猜测路径。

本文只规划任务，不宣称实现完成。落地时每个任务都必须先刷新源码锚点，再按任务卡验收。

### 适用范围

- 已存在、本计划**只 pin 不改语义**的读/建面：`GET /api/v1/tree`、`POST /api/v1/create-entry`（`is_directory=true`）。
- 新增产品写：`POST /api/v1/delete-entry`、`POST /api/v1/move-entry`（改名 = 同 parent 的 move）。
- 已存在、本计划**挂载 + 鉴权 + 文档对齐**的标签面：`POST /api/v1/tags`、`POST /api/v1/tags/list`、`GET /api/v1/tags/{name}`、`DELETE /api/v1/tags/{name}`。
- 路由：`src/api/api_router.rs` 的 `storage_only_routers_with`；`src/api/router/preview_router.rs` 的 `write_routers`；`src/api/router/tag_router.rs`。
- 服务：`src/ceres/api_service/{mod,mono_api_service,import_api_service}.rs`；落地复用 `land_api_tip_push`（`src/ceres/pack/api_tip_lander.rs`）。
- 测试：`tests/integration_api_write_trunk.rs`、`scripts/api_write_smoke_storage_only.sh`、`src/server/http_server.rs` 的 storage-only OpenAPI 锁。
- 文档：新建 `docs/refactoring/directory-entry-api.md`；同步 `docs/monorepo.md`、`docs/deploy-trunk.md`、`docs/refactoring/integration.md`。

### 非目标

- 不修改 `GET /tree` / `POST /create-entry` / `POST /edit/save` 的既有请求字段或成功语义。
- 不删除或移动**文件**；不预览/编辑 blob；不建文件（`is_directory=false` 保持既有 create-entry）。
- 不以 Git receive-pack delete command、parent-path 客户端 push 或 CL `apply_changes` 冒充产品 HTTP。
- 不把 list tags 从 `POST /tags/list` 改成 `GET`（文档改对齐程式，不改 wire）。
- 不把 `get_tag` / `delete_tag` 的硬编码 `repo_path="/"` 扩成任意 path（只文件化；路径级 get/delete 见 `DEFER-LB-03`）。
- 不接入 Review OAuth / Cedar enforce；不为 storage-only 打开 SSH receive-pack。
- 不实现 Libra 客户端（outgoing `DEP-LB-03`）。
- 不改 `import_dir` 下 ImportRepo 的 Git 多分支 / 客户端 tag 语义。

### 成功定义

- storage-only OpenAPI 同时列出 `create-entry`、`delete-entry`、`move-entry`、`/tags`、`/tags/list`、`/tags/{name}`，且仍排除 `/cl` / `/auth` / `/user`。
- `push_auth=token` 下无凭据的目录变更与 tag 写返回 401；path 未覆盖返回 403；`none` 下无 header 仍可写。
- 目录删除/移动后 `GET /tree` 与同栈 `git clone` / `git pull` 看到新树；trunk 成功 `cl_link=null`，零新 `mega_cl` / `refs/cl/*`。
- tag list 以 **POST** 为准；create/delete 在 trunk 走 `push_auth`；get/delete 无 path 选择器（handler 固定以 `/` 分发，服务层按 tag 名全局查找；LB-04 落地时精确化，见 LB-04 AC-7 与 `DEFER-LB-11`）。
- 契约正文 `docs/refactoring/directory-entry-api.md` 可被 Libra `DEP-MB-04` / `DEP-MB-05` 按 `file:line` pin。
- 非延后卡 `Lifecycle=done` 且 `Acceptance=complete`；review 最终 `PASS`。

## 已决议设计决策

### ADR-LB-01: 已有 API 只 pin，不改字段

- **Status:** Accepted
- **Context:** Libra 已按程式 pin `GET /tree` 与 `POST /create-entry`。改字段会打断其 MB-01/MB-04。
- **Decision:** 本计划不增删这两个端点的 query/body 必填字段，不改成功包络 `req_result` + `data`。契约页原样记录它们，作为消费者基线。
- **Alternatives considered:** 另开 versioned `/api/v2` — 拒绝（无版本协商，调用方只有这一面）。
- **Consequences:** 新能力只追加路径。
- **Revisit when:** 正式 versioned API 发布。

### ADR-LB-02: 目录变更是 parent-path tree 改写，不是 Git delete

- **Status:** Accepted
- **Context:** trunk receive-pack 拒绝 delete command（`monorepo.rs:1271`）。CL `apply_changes` 不是产品面。
- **Decision:** 删除 = 从**父目录 tree** 去掉该 directory item，写新 commit，经 `land_api_tip_push`（trunk）或既有 create-entry 的 CL 分支（review）前进 tip。移动/改名 = 同一套改写：源父去掉、目标父插入**同一 tree oid**（改名只改 `TreeItem.name`）。删除目录会丢掉该子树在新 tip 上的入口（TUI 确认由客户端做）。**禁止**构造 `CommandType::Delete`，**禁止**调用 `apply_changes`。
- **Alternatives considered:** 猜 `/delete-entry` 以外的 REST 形而不落地服务 — 拒绝；用 `git push` 删 — 拒绝（trunk 拒 delete，且不是本计划客户端）。
- **Consequences:** 空/非空目录同一条删除语义；不能「只删空目录」。父目录被删空时，服务端补写带时间戳的 `.gitkeep` 使其保留为空目录（LB-02 落地事实；与 create-entry 表示新建空目录的方式一致）。
- **Revisit when:** 需要回收对象 GC 或空目录专用语义。

### ADR-LB-03: 目录变更 wire（本计划指定的路径字符串）

- **Status:** Accepted
- **Context:** Libra `DEP-MB-04` 故意不猜 path。本计划必须给出可 pin 的字面量。
- **Decision:** 与 `create-entry` 对齐，用 **parent `path` + `name`**，不使用单一绝对 path 字段当权威。HTTP 状态与 create-entry 一样用 **200** + `CommonResult<T>`（不用 204）。

#### 已有（只记录）

| 操作 | Method | Path | 鉴权 | 请求 | 成功 `data` |
|---|---|---|---|---|---|
| 列一层 | `GET` | `/api/v1/tree` | 无 | query `path`（默认 `/`）、`refs` | `TreeResponse.tree_items[{name,path,content_type}]`；`file_tree` 仅祖先辅助，**不得**当导航权威 |
| 建目录 | `POST` | `/api/v1/create-entry` | 写：ADR-LB-04 | `CreateEntryInfo`：必填 `is_directory`,`name`,`path`；`content` 可 null/省略；`author_username`/`author_email` 可省略；`skip_build` **optional**，`#[serde(default)]` → `false`（Libra 一律送 `true`）；`mode` **optional**，默认 `EditCLMode::TryReuse(None)`——调用方应**省略**该键，不得送字符串 `"try_reuse"` | `CreateEntryResult{commit_id,new_oid,path,cl_link}`；trunk 上 `cl_link=null`；`path` 只作回执 |

#### 本计划新增

**`POST /api/v1/delete-entry`**

```json
{
  "path": "/project",
  "name": "old-dir",
  "author_username": null,
  "skip_build": true
}
```

| 字段 | 规则 |
|---|---|
| `path` | **必填**。父目录，rooted，默认语义与 create-entry 相同（根下用 `/`） |
| `name` | **必填**。要删的目录名；禁止 `/`、`.`、`..`、分隔符、NUL、控制字符 |
| `author_username` | **可选**。`Option<String>`；可省略或 JSON `null`。不参与鉴权。 |
| `skip_build` | **可选**。`bool`，`#[serde(default)]` → `false`。Libra 一律送 `true`。与 create-entry 同形。 |
| 目标 | 必须已存在且 `content_type=directory`；禁止删 `/` |
| 鉴权 | `authorize_trunk_api_write(path)`，path = **父目录** |
| HTTP | **200** + `CommonResult`（不用 204） |
| 成功 `data` | `{ "commit_id": "<hex>", "path": "/project/old-dir", "cl_link": null }`；**无** `new_oid`。`path` 只作回执。 |

**`POST /api/v1/move-entry`**

```json
{
  "from_path": "/project",
  "from_name": "old-dir",
  "to_path": "/project/other",
  "to_name": "new-dir",
  "author_username": null,
  "skip_build": true
}
```

| 字段 | 规则 |
|---|---|
| `from_path` / `from_name` | **必填**。源父 + 源名；源必须是 directory |
| `to_path` / `to_name` | **必填**。目标父 + 目标名；目标父必须已存在且为 directory |
| `author_username` | **可选**。同 delete-entry。 |
| `skip_build` | **可选**。同 delete-entry；Libra 一律送 `true`。 |
| 改名 | `from_path == to_path` 且 `from_name != to_name` |
| 拒绝 | 源目标相同；目标名已存在；把目录移进自己的子树；file 源；`/`；traversal；`import_dir` |
| 鉴权 | **两个** path（`from_path` 与 `to_path`）都必须通过 `authorize_trunk_api_write`；任一失败则不写 |
| HTTP | **200** + `CommonResult`（不用 204） |
| 成功 `data` | `{ "commit_id": "<hex>", "from_path": "/project/old-dir", "to_path": "/project/other/new-dir", "cl_link": null }`；**无** `new_oid`。返回路径只作回执。 |

校验失败与 create-entry 对齐：重复名 / 非法名 → 可诊断 4xx（现网 Duplicate name 走 `GitError::CustomError`，保持同一映射，不新发明 409 除非现网已有）。缺目录 → 404。auth → 401/403。

- **Alternatives considered:** `DELETE /entry?path=` — 拒绝（与 POST create-entry 不对称，且 query 里放写目标易进日志）；单一 `{from,to}` 绝对路径 — 拒绝（无法复用 create-entry 的 parent+name 校验）。
- **Consequences:** Libra client 必须按本表组包，不得再发明第三套字段名。
- **Revisit when:** 需要 bulk 或多条目事务。

### ADR-LB-04: 写鉴权复用 `authorize_trunk_api_write`

- **Status:** Accepted
- **Decision:** 目录变更 handler 调用既有 `trunk_write_requester`（非 trunk 返回 `None` 走 Review CL）。`push_auth=token`：Bearer 或 Basic 密码栏；`none`：无 header 允许，requester=`anonymous`。错误、JSON、trace 不得回显 token。list tree 与 tag list/get **不**送 / **不**要求 Authorization。
- **Alternatives considered:** 新 OAuth — 拒绝（storage-only 无 user router）。
- **Consequences:** 与 LFS / create-entry 同一威胁模型；`none` 仅受控网络。
- **Revisit when:** 独立于 push token 的 API credential。

### ADR-LB-05: 挂现有 `tag_router`；list 以程式为准；get/delete 保持 root

- **Status:** Accepted
- **Context:** 服务层已实现；storage-only 没挂。文档写 GET list 是错的。get/delete 硬编码 `/`。
- **Decision:**
  1. `storage_only_routers_with` **merge** `tag_router::routers()`。
  2. 不改 list 方法：仍是 `POST /api/v1/tags/list` + `PageParams<String>`。`pagination` 与 `additional` **都是必填 JSON key**（`common.rs:52-56`，无 `#[serde(default)]`）。server 把 `additional.trim().is_empty()` 视同 `/`（含空白）；调用方列 root 必须送 `additional:"/"`。
  3. create：`POST /api/v1/tags` + `CreateTagRequest`（见下表）。**权威 HTTP 状态是 handler 的 200** + `CommonResult<TagResponse>`；现网 OpenAPI 误写 201。LB-04 必须把 utoipa 改成 200 并加回归，不得让 201 与 200 并存。
  4. get / delete：路径仍是 `/tags/{name}`；**继续**只用 `repo_path="/"`；契约页写明「MVP 只操作 monorepo root tags」。（LB-04 落地时精确化：两条路由无 path 选择器，handler 固定以 `/` 分发，服务层按 tag 名全局查找；见 LB-04 AC-7 与 `DEFER-LB-11`。）
  5. **仅当** `push_policy=trunk`（含 storage-only）时，create/delete 调用 `authorize_trunk_api_write`：create 用 `req.path_context.as_deref().unwrap_or("/")`；**delete 无 body，授权 path 固定 `/`**。`push_tokens.paths=["/project"]` 这类不含 `/` 的 token 对 **每一次** tag delete，以及 **省略或显式 `path_context="/"`** 的 create，都返回 **403**。契约页必须警告 Libra：tag 写需要能覆盖 `/` 的 token（`paths` 省略/空 = whole repo）。Review 形态不引入这道闸。
  6. `docs/monorepo.md` 的 list 行改为 POST。

  | 类型 | 字段 | 规则 |
  |---|---|---|
  | `CreateTagRequest` | `name` | 必填 |
  | | `target` | 可选；serde alias `target_commit` |
  | | `path_context` | 可选；省略则 handler 用 `/`（也是 trunk 鉴权 path） |
  | | `tagger_name` / `tagger_email` / `message` | 可选。**无**请求键 `tagger` |
  | `PageParams<String>` | `pagination`,`additional` | **均必填** |
  | `TagResponse` | `name,tag_id,object_id,object_type,tagger,message,created_at` | `tagger` 是响应字符串 |
  | `DeleteTagResponse` | `deleted_tag`,`message` | |
- **Alternatives considered:** 把 list 改 GET 以迁就文档 — 拒绝（破坏已有 Review 调用方）；对 Review OAuth 调 tag — 拒绝（非本计划）；挂载但不鉴权 — 拒绝（匿名写 refs/tags）。
- **Consequences:** Libra 必须 POST list；不得假设 path 级 get/delete。
- **Revisit when:** `DEFER-LB-03` 给 get/delete 加上 path 选择器与 path 隔离。

### ADR-LB-06: Review 走既有 CL 分支；ImportRepo 拒绝

- **Status:** Accepted
- **Decision:** `write_routers` 同时挂在 Review 与 trunk。服务层照抄 `create_monorepo_entry`：`PushPolicy::Trunk` → `land_api_tip_push`；否则 `find_or_create_cl_for_edit`。`ImportApiService` 对 delete/move 返回与 create-entry 同类错误（不支持）。
- **Alternatives considered:** 只在 storage-only 挂 delete/move — 拒绝（调用方无法在 Review HTTP 上用同一路径做集成测试，且 `write_routers` 已是共享面）。
- **Consequences:** Review 成功可有 `cl_link`；trunk 必须为 null。
- **Revisit when:** Review 目录变更要独立出不造 CL 的模式。

### ADR-LB-07: Git 可见性

- **Status:** Accepted
- **Decision:** 目录变更成功后，对同一 path tip 的 `git clone` / `git fetch`+`pull` 必须看到删除或新路径。tag create/delete 后 `GET /tags/{name}` 与 `POST /tags/list` 一致；Git 客户端 push tag 仍拒绝。
- **Alternatives considered:** 只验 REST — 拒绝（与 AW-03 不一致）。
- **Consequences:** LB-05 黑盒用 curl+git，不用 libra 当协议客户端。
