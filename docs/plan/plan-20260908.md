# Storage-only SSH 只读对齐 HTTP（password token）计划（2026-09-08）

**模板版本：** v2；依据 [`plan-template.md`](plan-template.md)，核对日期 2026-09-08。

## 文档职责

本文解决「storage-only（`push_policy=trunk` + 显式 `git.push_auth`）下 SSH clone/fetch/pull 不可用或与 HTTP 读行为分叉」的缺口：今天 SSH 连接只走 `auth_publickey` → `UserStorage` 指纹查库，而 storage-only **没有用户系统**；HTTP 读则由 `git.anonymous_access` 与（`push_auth=token` 时）`[[git.push_tokens]]` 决定。目标是交付：**SSH upload-pack 与 HTTP upload-pack 在 storage-only 下共用同一读策略**——匿名开则 **storage-only** `auth_none` 放行；匿名关且 `push_auth=token` 时用 **SSH password = push token 密文**（复用 `lookup_push_token`）；**receive-pack 继续关闭**；review 形态保留公钥链（不因默认匿名而 Accept `auth_none`）。

本文只规划任务，不宣称实现完成。落地时每个任务都必须先刷新源码锚点（GC-01），再按任务卡验收。

### 适用范围

- SSH 认证：`auth_none`、`auth_password`（password token）、storage-only 下 publickey 与 UserStorage 的关系。
- SSH upload-pack 入口与既有 `check_upload_pack_access` 组合。
- storage-only 下仍拒绝 SSH receive-pack（既有 `ssh_receive_pack_enabled`）。
- 进程级 IT：trunk + `push_auth` 夹具上的 SSH clone / fetch / pull，以及 receive-pack 仍拒。
- 文档与样例：`docs/deploy-trunk.md`、`docs/refactoring/protocol.md`、`config/config-storage-only.toml`、本目录索引。

### 非目标

- **不打开** storage-only 的 SSH receive-pack / SSH 推送（永久非目标于本计划；推送仍走 smart HTTP）。
- **不实现** 配置挂公钥（`ssh_public_keys`）——登记为 `DEFER-SP-01`。
- **不实现** SSH pure `git-lfs-transfer`；LFS 字节仍走 HTTP / hybrid `git-lfs-authenticate`（与 plan-20260909 一致）。
- **不改** review 形态（省略 `push_auth`）的 UserStorage 公钥认证主路径。
- **不改** HTTP 推送鉴权、`token.paths` 的**推送**前缀语义；本计划读侧与现状 HTTP 读一致（**读不查 `paths`**，除非未来双通道一起改——不在本计划）。
- **不 bump minor/major**；实现卡一律 **patch +1**。

### 成功定义

- storage-only + `anonymous_access=true`：无 UserStorage SSH key、无 password 亦可 **SSH clone**（anon/`none` 轴以 clone 为进程验收；fetch/pull 与 clone 同会话闸，不单独立项 IT）。
- storage-only + `anonymous_access=false` + `push_auth=token`：无 password 拒；password = 有效 `[[git.push_tokens]]` 密文则 SSH **clone/fetch/pull** 成功，身份为 token `name`；与同配置 HTTP Bearer/Basic 读一致。
- storage-only 下任意 SSH receive-pack 仍失败（显式错误或 channel failure）。
- review 形态既有 `integration_git_ssh` 公钥路径不回归。
- 全部非延后任务卡 `Lifecycle=done` 且 `Acceptance=complete`；每张实现卡发布均为 **patch +1** + commit + `libra push origin main`（无 minor）。

## 已决议设计决策

### ADR-SP-01: SSH password = `[[git.push_tokens]]` 密文

- **Status:** Accepted
- **Context:** storage-only 在 `anonymous_access=false` 时 HTTP 用 Bearer/Basic（password 字段）对静态 token；SSH 需要同语义且不引入用户系统。
- **Decision:** 当 `git.push_auth == Some(Token)` 时实现 `auth_password`：以客户端提供的 password 调用既有 `lookup_push_token`；命中则 `authenticated_user = token.name` 并 `Auth::Accept`；未命中 `Auth::Reject`。SSH username 字段**不参与**判定（与 HTTP Basic 忽略 username、只取 password 对齐）。`push_auth=none` / 省略 `push_auth`（review）**不**走本通道。
- **Alternatives considered:** (1) 配置挂公钥——拒绝为本切片，运维双凭据，见 DEFER-SP-01；(2) username=token 密文——拒绝，易进进程列表日志。
- **Consequences:** 客户端需 password 认证（`SSH_ASKPASS` / `sshpass` / 定制 `GIT_SSH_COMMAND`）；服务端不新增配置键。
- **Revisit when:** DEFER-SP-01 落地或合规禁止 SSH password。

### ADR-SP-02: 仅 storage-only 在 `anonymous_access=true` 时提供 SSH `auth_none`

- **Status:** Accepted
- **Context:** HTTP 匿名读已由 `check_upload_pack_access` 放行；storage-only 无 UserStorage 公钥。但 OpenSSH 客户端会先尝试 `none`：若 review（省略 `push_auth`）在默认 `anonymous_access=true` 下也 Accept `auth_none`，则永远不会落到 `auth_publickey`，**SSH receive-pack / 认证推送会失去身份**。
- **Decision:** **仅当 `git.storage_only()`（`push_auth.is_some()`）且 `anonymous_access=true`** 时实现 `auth_none` → `Auth::Accept`。review（省略 `push_auth`）**不**提供成功的 `auth_none`（Reject 或不实现），保留既有 publickey 链。`anonymous_access=false` 时 `auth_none` 一律 Reject。
- **Alternatives considered:** (1) 全形态开 `auth_none`——拒绝（破坏 review 推送）；(2) 独立只读 SSH 端口——拒绝（运维面过大）。
- **Consequences:** storage-only 匿名读与 HTTP 对齐；review 行为不变。须补 IT：review + `anonymous_access=true` 下 seeded 公钥 **push** 仍成功。
- **Revisit when:** 若产品提供独立只读 SSH listener。

### ADR-SP-03: storage-only 仍禁止 SSH receive-pack；review 公钥路径保留

- **Status:** Accepted
- **Context:** TP-20 关闭 SSH 推送是安全边界；本计划只补读。
- **Decision:** 不改 `ssh_receive_pack_enabled` 语义。review（省略 `push_auth`）继续用 UserStorage `auth_publickey`。**选定：** storage-only（`push_auth.is_some()`）时 `auth_publickey` → `Auth::Reject`（可提示改用 password / none），**不调用** `UserStorage::search_ssh_key_finger`。
- **Alternatives considered:** storage-only 仍接受播种密钥——拒绝，违背「无用户系统」。
- **Consequences:** 文档必须写清客户端怎么用 password；IT 覆盖 receive-pack 仍拒。
- **Revisit when:** 产品要求 SSH 推送（新计划，非本切片）。

### ADR-SP-04: `push_auth=none` 的 SSH 读矩阵（storage-only 运营对齐）

- **Status:** Accepted
- **Context:** 评审要求显式覆盖 `none`。HTTP 在 `push_auth != Some(Token)` 且客户端出示凭据时，`git_http_auth` **仍会**查询 `UserStorage` mono access token（`http.rs:155-181`）。storage-only 产品不变量是**无用户系统 / 空 UserStorage**；在该不变量下 HTTP 也建不成身份。但若有人在 trunk+`none` 误播种 UserStorage，HTTP 可读而 SSH 不可读——这是**残留分叉**，本计划**不**用改 HTTP 或在 SSH 重开 UserStorage 来抹平。
- **Decision:**
  | `push_auth` | `anonymous_access` | SSH 读会话 | 对齐口径 |
  |---|---|---|---|
  | `token` | `true` | `auth_none` Accept | 同 HTTP 匿名读 |
  | `token` | `false` | `auth_password` + `lookup_push_token` | 同 HTTP Bearer/Basic password |
  | `none` | `true` | `auth_none` Accept | 同 HTTP 匿名读 |
  | `none` | `false` | **fail-closed**：`auth_none` Reject；`auth_password` Reject；`auth_publickey` Reject | **运营对齐**：空 UserStorage 下 HTTP 同样不可读；**本计划不改 HTTP none 臂**（既不接受静态 token，也不关掉其 UserStorage 回退） |
  | 省略（review） | `true` | **无**成功 `auth_none`；UserStorage `auth_publickey` | 保护公钥推送（ADR-SP-02） |
  | 省略（review） | `false` | 既有 UserStorage `auth_publickey` | 不改 |
- **Alternatives considered:** (1) none+匿名关接受 password——拒绝（给 `none` 第二凭据面）；(2) SSH 对 none 也走 UserStorage——拒绝（违背 storage-only 无用户系统）；(3) 本切片改 HTTP 使 none+匿名关对任何凭据 fail-closed——拒绝为本切片范围，见 DEFER-SP-04。
- **Consequences:** 运维若 `none` 且要关匿名读，应改回 `token` 或打开 `anonymous_access`；文档须写明「勿在 trunk+none 依赖 UserStorage」；IT 覆盖 SSH none±匿名。残留分叉（误播种 UserStorage）登记为 DEFER-SP-04。
- **Revisit when:** DEFER-SP-04 启动（HTTP none 臂 fail-closed）或产品要求 SSH 接受 UserStorage。
