# Storage-only 形态 Git 协议黑盒 smoke 计划（2026-09-06）

**模板版本：** v2；依据 [`plan-template.md`](plan-template.md)，核对日期 2026-09-10（文件名按指定保留 `plan-20260906`）。

## 文档职责

本文解决：**如何以黑盒方式验收 storage-only / trunk 形态的全部 Git 协议面**——被测对象是 compose 栈内常驻的 `monoengine`（挂载 `config/config-storage-only.toml`），观察者是栈外 `git-smoke` 容器内的真实 **`git` / `git-lfs` / OpenSSH `ssh` 客户端**，只经已发布端口（HTTP `8000`、SSH `2222`）与公开协议交互；不进入 crate 内部、不把 `cargo test --test integration_git_*` 当作本计划的主验收门。

**测试工具硬约束：** 协议黑盒的唯一客户端工具链是 **`git`（及配套 `git-lfs`、`ssh`）**。本仓 VCS 客户端 **`libra` 不得作为协议测试工具**（不得用 `libra clone` / `libra push` / `libra fetch` 等冒充或替代 `git` 场景）。`libra` 仅用于本计划落地后的**仓库提交与推送**（`libra add` / `commit` / `push origin main`），与黑盒观察者正交（ADR-SO-09）。

触发缺口：`docker-compose-storage-only.yml` 已挂 `git-smoke`，但注释仍调用 review/CL 语义的 `scripts/git_protocol_smoke.sh`；样例 `config/config-storage-only.toml` 同时存在两处生效的 `push_auth`（`token` 与 `none`）。

目标：交付独立 `scripts/git_protocol_smoke_storage_only.sh` + compose 夹具；**每一个稳定黑盒 case 对应一张 implementation 任务卡**（G-01）；夹具卡 SO-01 与收口卡 SO-06 不承载协议 case；**不**改写 review smoke；**不**用 IT 替代 compose 黑盒门；**不**用 `libra` 当协议客户端。

本文只规划任务，不宣称实现完成。

### 黑盒边界（本计划硬约束）

| 允许 | 禁止（作为 SO 验收主证据） |
|---|---|
| compose 起停、`service init`、卷生命周期 | 改 `src/**` 作为本计划行为轴 |
| **`git` / `git-lfs` / `ssh`** 经已发布端口 | **`libra` 作为协议客户端**（任何 `libra <vcs-verb>` 对 monoengine 的 clone/push/fetch/ls-remote） |
| 样例/override、smoke 脚本、compose、文档 | `cargo test --test integration_git_*` 作为场景卡 VER 主门 |
| tip / refs / LFS 内容 / 退出码 / 稳定 stderr | 断言库内私有 API；seed `access_token` 表；以新 `refs/cl/*` 作为 trunk 成功条件 |

进程级 IT 仍是 plan-20260908/09 回归权威；本计划只交叉引用。

## 已决议设计决策

### ADR-SO-01: 独立脚本

- **Status:** Accepted
- **Decision:** 新增 `scripts/git_protocol_smoke_storage_only.sh`；不改 `git_protocol_smoke.sh` CL 默认路径。

### ADR-SO-02: Trunk 写断言

- **Status:** Accepted
- **Decision:** tip 相对 push 前前进；禁止「必须新 `refs/cl/*`」；tag push 失败无残留。

### ADR-SO-03: 凭据

- **Status:** Accepted
- **Decision:** Basic `http://x:<token>@monoengine:8000/<path>`；不 seed `access_token` 表；证据脱敏。

### ADR-SO-04: LFS 网内 URL

- **Status:** Accepted
- **Decision:** `config/compose.env.storage-only.lfs-innetwork` 设 `MEGA_HTTP__PUBLIC_BASE_URL=http://monoengine:8000`（及必要 LFS HTTP_URL）。

### ADR-SO-05: Init 与路径契约

- **Status:** Accepted
- **Decision:**
  1. 空卷：`docker compose -p monoengine-trunk -f docker-compose-storage-only.yml up -d --wait` 后  
     `docker compose -p monoengine-trunk -f docker-compose-storage-only.yml exec -T monoengine monoengine --config /etc/monoengine/config.toml service init --yes`  
     （ENTRYPOINT 已含二进制名则去掉重复前缀；最终命令写回脚本 `-h` 与 deploy-trunk）。
  2. 干净重跑（破坏性，文档标明）：  
     `docker compose -p monoengine-trunk -f docker-compose-storage-only.yml down -v`  
     后再执行 §1 的 `up -d --wait` + `service init --yes`。
  3. Smoke 根 URL `/` 为黑盒夹具；与 deploy-trunk §9 日常子路径并列。

### ADR-SO-06: none 具名服务端配置

- **Status:** Accepted
- **Decision:** 默认样例只留 `push_auth=token`；新增 `config/config-storage-only.none.toml` + `docker-compose-storage-only.auth-none.yml` 覆盖挂载。opt-in 必须双 `-f` + `--force-recreate monoengine`。禁止 profile 换卷幻想；禁止只改客户端 env。

### ADR-SO-07: Compose 黑盒验收边界

- **Status:** Accepted
- **Decision:** 场景卡（SO-02..04、SO-07..25）的 VER 主证据必须是 compose 上真实 **`git`/`git-lfs`/`ssh`** 调用。IT 仅交叉引用。提交仍走 AGENTS 三门+双 build（不计 VER 分母）。

### ADR-SO-08: 单 case 过滤器与共享黑盒调用

- **Status:** Accepted
- **Decision:**
  1. 脚本支持 `MONOENGINE_SMOKE_CASE=<exact case name>`：只跑该 `run_case`；其余不执行；未匹配则非 0。未设置则跑当前脚本已注册的全部 case（受 `PUSH`/`LFS`/`SSH URL` 门控）。
  2. 场景卡 VER 默认形态（可复制；变量仅替换 `CASE` 与必要 env）：
     ```bash
     docker compose -p monoengine-trunk -f docker-compose-storage-only.yml up -d --wait
     # 若卷未 init：按 ADR-SO-05 §1 执行 service init --yes
     docker compose -p monoengine-trunk -f docker-compose-storage-only.yml --profile smoke \
       exec -T \
       -e MONOENGINE_HTTP_REPO_URL="${MONOENGINE_HTTP_REPO_URL:-http://monoengine:8000/}" \
       -e MONOENGINE_SMOKE_CASE='<CASE>' \
       git-smoke bash /repo/scripts/git_protocol_smoke_storage_only.sh
     ```
     输出必须含 `PASS: <CASE>`。场景卡 Verification **必须**把「输出含 `PASS: <CASE>`」与「summary 匹配 `0 failed`」写成**两条独立** checklist（G-03；禁止用「且」合并）。脚本内部协议动作必须调用 `git` / `git-lfs` / `ssh`（见 ADR-SO-09），不得调用 `libra`。需要落盘时按 ADR-SO-10 §2 `tee` 到宿主日志。
  3. Token 写 URL：`http://x:<token>@monoengine:8000/`（token 来自样例/`compose` secret；证据脱敏）。
  4. SSH：`MONOENGINE_SSH_REPO_URL=ssh://git@monoengine:2222/`；known_hosts 命令以 deploy-trunk 为准（首张 SSH 场景卡写入）。
  5. none / LFS：在上述调用前按 ADR-SO-06 / ADR-SO-04 切换栈；卡内写全命令，不省略。

### ADR-SO-09: 协议测试工具 = git（禁止 libra 客户端）

- **Status:** Accepted
- **Decision:**
  1. **观察者工具链：** `git`（必选）、`git-lfs`（仅 LFS case）、OpenSSH 客户端 `ssh`（仅 SSH case）。宿主于 `git-smoke` 镜像（或文档登记的等价环境，仍须提供上述二进制）。
  2. **禁止：** 在 `scripts/git_protocol_smoke_storage_only.sh`（及本计划新增的任何 smoke 辅助脚本）中，以 `libra` 执行对 monoengine 的协议操作（含但不限于 `libra clone`、`libra fetch`、`libra pull`、`libra push`、`libra ls-remote`，以及把 `libra` 设为 `GIT_EXEC_PATH` / 替换 `git` 包装）。
  3. **正交允许：** 本仓发布动作继续使用 `libra add` / `libra commit` / `libra push origin main`（GC-SO-01）；该路径不进入场景卡 VER、不进入 smoke 脚本协议路径。
  4. **守卫（可复制；`rg` 退出码模板）：** 下列命令必须以退出码 **1** 结束（零命中）。退出码 `0` = 发现禁止调用；`>1` = 命令失败，不得当作通过。使用 `--regexp`（勿用 `-E`：ripgrep 15+ 将 `-E` 解析为 encoding）：
     ```bash
     set +e
     rg -n --regexp '(^|[|;&]|\$\(|`)[[:space:]]*libra[[:space:]]+(clone|fetch|pull|push|ls-remote)\b' \
       scripts/git_protocol_smoke_storage_only.sh
     rc=$?
     set -e
     test "$rc" -eq 1
     ```
     注释中说明「仓 VCS ≠ 测试客户端 / 不用 libra 作协议客户端」允许保留；不得以注释豁免上述命令形式的调用。
- **Alternatives:** 用 Libra 客户端测 monoengine 兼容性 — **拒绝**（本计划目标是 Git 协议面黑盒，不是 Libra↔monoengine 互通）。

### ADR-SO-10: 测试结束后如何获取输出结果

- **Status:** Accepted
- **Decision:** 结果获取分三层，**不以容器内交互式翻看为验收路径**。

  1. **主通道 = 宿主 stdout/stderr + 进程退出码（必选）**  
     `docker compose … exec -T git-smoke bash …/git_protocol_smoke_storage_only.sh` 在**前台**跑完后：
     - 终端即时打印每条 `==> <case>` / `PASS: <case>` / `FAIL: <case>`，末行  
       `git protocol smoke summary: <N> passed, <M> failed`（basename 可含 `storage_only`，但必须含 `summary:` 与 `failed`）。
     - **退出码 0** 当且仅当 `failed=0`（含仅跑单 case 时该 case PASS）；任一 FAIL → 非 0。  
     VER / Agent 验收读的就是这段输出与退出码，无需另开日志服务。

  2. **持久证据 = 宿主 tee 日志文件（推荐；SO-01 文档化）**  
     在宿主把 compose exec 整段 stdout+stderr 写入仓库外或 `target/` 下（`target/` 已 gitignore，适合本地证据）：
     ```bash
     mkdir -p target/tmp
     LOG="target/tmp/so-smoke-$(date -u +%Y%m%dT%H%M%SZ)-${MONOENGINE_SMOKE_CASE:-all}.log"
     set -o pipefail
     docker compose -p monoengine-trunk -f docker-compose-storage-only.yml --profile smoke \
       exec -T \
       -e MONOENGINE_HTTP_REPO_URL="${MONOENGINE_HTTP_REPO_URL:-http://monoengine:8000/}" \
       -e MONOENGINE_SMOKE_CASE="${MONOENGINE_SMOKE_CASE:-}" \
       git-smoke bash /repo/scripts/git_protocol_smoke_storage_only.sh \
       2>&1 | tee "$LOG"
     echo "SO smoke log: $LOG"
     ```
     测试结束后：打开 `$LOG`，或 `rg -n '^(PASS|FAIL|.*summary:)' "$LOG"`。  
     **禁止**把含 token 的完整 URL 明文提交进仓库；日志若含凭据，只留本地 / 脱敏后再归档。

  3. **可选工作区工件 = 宿主 bind-mount（排障用，非 PASS 主证据）**  
     compose 已挂 `${MONOENGINE_IT_GIT_WORKDIR:-/tmp/monoengine-trunk-git}:/work`。clone/push 产生的工作树在**宿主**该目录可读（`ls` / `git -C … log`）。  
     case PASS/FAIL **不以**该目录内容为唯一判据；目录可被下次 run 覆盖。需要保留时由执行者自行 `cp -a` 到带时间戳目录。

  4. **不做：** 不要求把结果写进 monoengine DB；不要求 CI artifact API（workflows 空 → DEFER-SO-02）；不要求从 `docker logs monoengine` 解析协议 PASS（服务端日志仅辅助排障）。

- **Alternatives:** 只写容器内 `/tmp` 无 tee — 拒绝（`exec` 结束后易丢，且 `-T` 无 TTY 时仍应落宿主文件）。
