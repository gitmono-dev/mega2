# Storage-only Git 协议 compose smoke 计划（2026-09-06）

**模板版本：** v2；依据 [`plan-template.md`](plan-template.md)，核对日期 2026-09-10（文件名按指定保留 `plan-20260906`）。

## 文档职责

本文解决：`docker-compose-storage-only.yml` 已挂 `git-smoke`（`monoengine-git-smoke:3.7.1`），但注释仍调用 **review/CL** 语义的 `scripts/git_protocol_smoke.sh`（成功条件含新 `refs/cl/*`）。在 `push_policy=trunk` 上会把正确行为判失败。另：样例 `config/config-storage-only.toml` 当前同时存在两处**生效**的 `push_auth`（`token` 与 `none`），compose 挂载后基线不确定。

目标：交付**独立** storage-only/trunk smoke 脚本 + 可重复的 compose 夹具（配置修复、init、路径契约、none/LFS override），覆盖本形态全部 **Git 协议面**场景；同步文档进各行为卡；**不**改写 review smoke 默认语义。

本文只规划任务，不宣称实现完成。

### 适用范围

- 新脚本：`scripts/git_protocol_smoke_storage_only.sh`（ADR-SO-01）。
- 驱动：`docker-compose-storage-only.yml` + `--profile smoke` 的 `git-smoke`（复用镜像）。
- 配置修复与 override：`config/config-storage-only.toml`（去掉双重生效 `push_auth`）；`config/config-storage-only.none.toml` + `docker-compose-storage-only.auth-none.yml`（ADR-SO-06）；可选 `config/compose.env.storage-only.lfs-innetwork`（ADR-SO-04）。
- 场景矩阵（「全部场景」= 下表）：

| 轴 | 场景 | 默认栈 |
|---|---|---|
| HTTP 只读 | ls-remote / clone / fetch / v2 fetch / shallow / v2 ls-remote / blob:none | 是 |
| HTTP 写 token | push 推进约定 tip；不把新 `refs/cl/*` 当成功条件；tag push 失败 | 是 |
| HTTP LFS | push→pull→cmp→locks；网内 `PUBLIC_BASE_URL` | opt-in |
| SSH 只读 | 对称 7 项（默认匿名开 → auth_none） | 是 |
| SSH 写负例 | receive-pack 必须失败 | 是 |
| HTTP 写 none | 匿名 push + tag reject | opt-in（双 `-f` override） |

### 非目标

- 不修改 `scripts/git_protocol_smoke.sh` 的 CL 默认断言（永久非目标）。
- 不新建/改 pin `Dockerfile.git-smoke`（当前不缺工具）。
- 不把 IT（`integration_git_*`）搬进 shell。
- 不测 `storage_type` 切换作为协议场景。
- 不实现 SSH LFS transfer；不打开 SSH receive-pack。
- 不启用 Blake3 哈希键值产品路径（plan-20260907）。
- password-anon-off 完整 compose 矩阵 → `DEFER-SO-01`。

### 成功定义

- 修复后样例仅一处生效 `push_auth=token`；`config validate` 通过。
- 文档化 init + 卷策略后，脚本在 compose 栈上：HTTP 读/写、SSH 读、receive-pack 负例绿。
- LFS / none opt-in 有具名 override 与可复制命令。
- 各行为卡含对应文档（G-02）；SO-06 索引收口。
- 非延后卡 `done`/`complete`；本计划文档 Codex **PASS**。

## 已决议设计决策

### ADR-SO-01: 独立脚本

- **Status:** Accepted
- **Decision:** 新增 `scripts/git_protocol_smoke_storage_only.sh`；不改 `git_protocol_smoke.sh` CL 默认路径。
- **Alternatives:** `MODE=trunk` — 拒绝。

### ADR-SO-02: Trunk 写断言

- **Status:** Accepted
- **Decision:** tip 相对 push 前前进；禁止「必须新 `refs/cl/*`」；tag push 失败无残留。

### ADR-SO-03: 凭据

- **Status:** Accepted
- **Decision:** Basic `http://x:<token>@monoengine:8000/<path>`；不 seed `access_token` 表；证据脱敏。

### ADR-SO-04: LFS 网内 URL

- **Status:** Accepted
- **Decision:** 具名 `config/compose.env.storage-only.lfs-innetwork` 设 `MEGA_HTTP__PUBLIC_BASE_URL=http://monoengine:8000`（及必要的 LFS HTTP_URL）。

### ADR-SO-05: Init 与路径契约

- **Status:** Accepted
- **Decision:**
  1. **空卷 bootstrap（可复制）**：`docker compose -p monoengine-trunk -f docker-compose-storage-only.yml up -d --wait` 后执行  
     `docker compose -p monoengine-trunk -f docker-compose-storage-only.yml exec -T monoengine monoengine --config /etc/monoengine/config.toml service init --yes`  
     （若镜像 ENTRYPOINT 已含二进制名，则去掉重复的 `monoengine` 前缀——实现时以容器内 `monoengine --help` 为准，并把**最终**一行写回脚本 `-h` 与 deploy-trunk）。  
  2. **卷生命周期**：数据在 named volume `monoengine-trunk-data`；已 init 则跳过；**干净重跑** = `docker compose -p monoengine-trunk -f docker-compose-storage-only.yml down -v` 后重新 up + init（破坏性，文档标明）。  
  3. **Smoke 路径**：默认根 URL `http://…@monoengine:8000/`（`MONOENGINE_SMOKE_REPO_PATH=/`）为测试夹具；与 `deploy-trunk.md` §9 日常子路径建议并列，不互相覆盖。

### ADR-SO-06: none 具名服务端配置

- **Status:** Accepted
- **Decision:** 默认样例只留 `push_auth=token`；注释掉误生效的 `none`；新增 `config/config-storage-only.none.toml`（无 tokens）。另增 **compose override 文件** `docker-compose-storage-only.auth-none.yml`，其唯一职责是把 `monoengine` 的配置卷从 `config-storage-only.toml` **覆盖挂载**为 `config-storage-only.none.toml`（同 service 名、同项目）。opt-in Verification **必须**使用双 `-f` 链：
  ```bash
  docker compose -p monoengine-trunk \
    -f docker-compose-storage-only.yml \
    -f docker-compose-storage-only.auth-none.yml \
    up -d --wait --force-recreate monoengine
  ```
  **禁止**仅靠 Compose `profiles` 期望同名服务换卷（profile 不能改写已定义 volume）；**禁止**只改客户端 env 冒充 none。
