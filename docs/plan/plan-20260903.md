# Monorepo 初始 Object-ID 配置计划（2026-09-03）

**模板版本：** v2；依据 [`plan-template.md`](plan-template.md)，核对日期 2026-09-03。

## 文档职责

本计划交付一个可配置、可验证的 Monorepo 初始 object graph：空根仓库按
`[monorepo].object_format` 选择 SHA-1 或 SHA-256 生成 seed commit、tree 与 blob
ID。计划将 bootstrap 能力与尚未实现的 repository format、Git wire、pack 和
BLAKE3 能力明确隔离。

### 适用范围

- `MonoObjectFormat` 的默认值、解析、严格字段白名单、reload restart 报告和配置样例。
- `MonoService` 的同步初始 object graph 建构、受控 `service init --yes` 入口，以及一般服务的 SHA-256 fail-close。
- PostgreSQL transaction-scoped advisory lock 与 strict root-ref insert，避免不同格式的并发初始化产生混合 graph 或假成功。
- SHA-1 / SHA-256 ID kind 与 thread-local 状态还原测试。
- BLAKE3 正确拼写的保留接口及 fail-closed 验证。

### 非目标

- 不持久化 repository object format，不转换已有 root ref。
- 不修改 Ceres v1/v2 capability、40 位 zero ID、want/have、receive-pack、pack/idx 或异步 hash context。
- 不实现 BLAKE3，不接受错误拼写 `black3`。
- 不宣称 SHA-256 初始图能够由当前服务 clone、fetch 或 push。

### 成功定义

- 未配置时保持 SHA-1 / 40 位 ID。
- `object_format = "sha256"` 时，初始 commit、tree、blob 和 tree item 均为 SHA-256 / 64 位 ID。
- `blake3` 被识别，却在 validate、converter 和 service initializer 写 root ref 前拒绝。
- 临时 hash kind 仅包住同步 builder，在任何 storage await 前还原。
- 普通 `service http` / `ssh` / `multi` 在任何 startup side effect 前拒绝 `sha256`；只有 `service init --yes` 可进行一次性 SHA-256 bootstrap 并退出。
- 同时请求 SHA-1 与 SHA-256 bootstrap 时，恰有一个格式能建立 root；另一个必须以 incompatible 错误退出。

## 已决议设计决策

### ADR-HSH-01：以配置固定空仓初始图的 SHA kind

- **状态：** Accepted
- **决策：** 新增 `monorepo.object_format`；canonical 值为 `sha1`、`sha256`、`blake3`，前两项 SHA 值可用，默认 `sha1`。
- **后果：** 配置变更不转换已有 root ref；该缺口不得用隐式重新 hash 补偿。

### ADR-HSH-02：0.8.x thread-local 仅限同步 builder

- **状态：** Accepted
- **决策：** `MegaModelConverter::init` 使用私有 RAII guard，完整覆盖同步 graph construction，返回前还原。
- **后果：** 不在 `AppContext` 全局设置，也不跨 `await`；异步 runtime 仍不是 SHA-256 safe。

### ADR-HSH-03：BLAKE3 接口 fail-closed

- **状态：** Accepted
- **决策：** `MonoObjectFormat::Blake3` 可解析，resolver、`Config::validate` 和 `init_monorepo` 均拒绝。
- **后果：** 不会 fallback 到 SHA-1，也不会接受 `black3` 拼写。

### ADR-HSH-04：bootstrap 与服务格式分离

- **状态：** Accepted
- **决策：** 只交付 initial graph；不改变 Ceres/pack 的 SHA-1 行为或 capability。`AppContext::new` 和普通 `service http` / `ssh` / `multi` 只接受 SHA-1；`service init --yes` 是唯一可进入 SHA-256 builder 的一次性入口。该入口要求既有 config，并只装配 DB、必要时 readonly Vault、object store 与 MonoService。
- **后果：** SHA-256 bootstrap 完成即退出，不能得到一个可继续运行的 Git server；既有 root ref 宽度不匹配时 fail-close，而不是静默跳过或转换。该入口不会启动 Redis、notification、sidebar、reload watcher 或 listener；DB migration 与 graph/object-store 写入仍是命令预期副作用。若 object-storage credential 使用 `vault://`，readonly Vault 的凭据读取、audit 与既有 key-file 权限收紧仍是必要的 credential-access 副作用，但不会初始化 Vault state。

### ADR-HSH-05：以 PostgreSQL transaction advisory lock 串行 root 初始化

- **状态：** Accepted
- **决策：** `initialize_monorepo` 在同一数据库交易开始时取得固定 `pg_advisory_xact_lock`，随后才读取 root、建构 graph、strict insert root ref，并在 commit 前重新读取验证。项目配置和连接层只支持 PostgreSQL。
- **后果：** 采用该路径的并发 bootstrap 会串行；后到请求读取到既有 root 后按 format fail-close。xact lock 在 commit、rollback 或连接断开时自动释放，不会污染 `mega_refs`。旧 binary/direct writer 仍可能绕过锁，因此 root ref conflict 不可由 generic `ON CONFLICT DO NOTHING` 吞掉；对象存储在 DB transaction 外，失败时的 orphan-object 语义维持现状。

## 全局工程约束

- GC-HSH-01：未知 / BLAKE3 format fail-closed，不作 SHA-1 fallback。
- GC-HSH-02：初始 graph 内每个 derived ID 都属于所选 SHA kind。
- GC-HSH-03：不新增跨 await 的 TLS state，不新增生产 `unwrap` / `expect`。
- GC-HSH-04：sample、generated template、config docs 和 Monorepo docs 同步。
- GC-HSH-05：不作端到端 SHA-256 / BLAKE3 Git 兼容宣称。
- GC-HSH-06：普通服务的 SHA-256 / BLAKE3 拒绝发生在 DB、Vault、Redis、notification 等 startup side effect 前。
- GC-HSH-07：root 初始化锁、root 检查、strict root insert 和最终 root 验证在同一 PostgreSQL transaction 内；任何 object-format 冲突不得报告成功。

### 故障恢复矩阵

| 故障点 | 可接受残留 | 恢复动作 | 禁止结果 |
|---|---|---|---|
| `blake3` config | 无 root graph 写入 | 改为 SHA 值或等待 0.9.0 | silent SHA-1 fallback |
| storage write / txn failure | 遵循现有 orphan-object 语义 | retry / cleanup policy | 报告部分 graph 成功 |
