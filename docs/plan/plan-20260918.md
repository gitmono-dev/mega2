## 文档职责

本文解决：storage-only / `push_policy=trunk` 已能删移**目录**、能挂 tag HTTP，但**不能**删移文件；tag list 仍是 POST（文档曾长期写成 GET）；get/delete 无 path 选择器且按名全局查找。目标是在既有 `delete-entry` / `move-entry` 上扩文件分支，把 list 改成唯一的 GET，并为 get/delete/list/create 落地 path 隔离。

本文只规划任务，不宣称实现完成。落地时每个任务都必须先刷新源码锚点，再按任务卡验收。

### 适用范围

- 扩既有写：`POST /api/v1/delete-entry`、`POST /api/v1/move-entry`（仍是 parent + name；加 `is_directory`，默认目录）。
- 改 list wire：唯一 list 为 `GET /api/v1/tags/list`；`POST /tags/list` 回 **405**。
- path 级 tag：`GET|DELETE /api/v1/tags/{name}?path=`；`mega_tag.path` 迁移；查找键 `(path, name)`。
- 路由 / 服务：`src/api/router/{preview_router,tag_router}.rs`；`src/ceres/api_service/mono_api_service.rs`；`src/jupiter/storage/mono_storage.rs`；`src/callisto/mega_tag.rs`；`src/jupiter/migration/`。
- 测试：`tests/integration_api_write_trunk.rs`、`scripts/api_write_smoke_storage_only.sh`、三份 OpenAPI 锁。
- 文档：[`docs/refactoring/directory-entry-api.md`](../refactoring/directory-entry-api.md)、[`docs/user-guide.zh.md`](../user-guide.zh.md)、[`docs/deploy-trunk.md`](../deploy-trunk.md)、[`docs/refactoring/integration.md`](../refactoring/integration.md)。

### 非目标

- 双方法窗口、`/api/v2`、把 list 留成 POST。
- 新开 `delete-file` / `move-file` 路径。
- Git delete command、`apply_changes`、ImportRepo 产品删移、blob / LFS / Media GC。
- path 级 tag 的 **target-commit 归属**校验（`DEFER-LB-11` 剩余面）；`search_tree_for_update` 类型化 400（`DEFER-LB-07`）；SQL 前缀无边界（`DEFER-LB-09`）；读 tree 与落地窗口（`DEFER-LB-10`）。
- 空目录-only 删除（`DEFER-LB-04`）、Libra TUI（`DEFER-LB-05`）、Review OAuth（`DEFER-LB-06`）、README 产品写列表（`DEFER-LB-08`）、Cedar。

### 成功定义

- `is_directory` 省略 / `true` 仍只删移目录；`false` 删移 `Blob` / `BlobExecutable`；两边都没有 → 404。
- 文件删移后 `GET /tree` 与同栈 `git clone` / `git pull` 看到新树；trunk `cl_link=null`；同 blob oid 在 move 后保留。
- list 只有 GET；POST `/tags/list` 为 405；缺 query 键或非法 query → extractor **400**（axum 0.8 `Query`，纯文本）；`per_page=0` 为 handler **400** + `CommonResult`（不再 panic）。
- get/delete 接受 `?path=`（省略或空 = `/`）；查找与 create 重名、list 过滤都以 `(path, name)` 为准；delete 鉴权 path = 选择器 path。
- 非延后卡 `Lifecycle=done` 且 `Acceptance=complete`；每张实现卡独立双评最终 `PASS`。

## 已决议设计决策

实现时若需偏离本节，必须先修改计划并说明原因，不得在代码中静默改语义。

### ADR-FT-01: `is_directory` 可选、默认目录

- **Status:** Accepted
- **Context:** create-entry 允许同名 blob 与 tree 并存（mode-scoped）。60917 的 delete/move 只匹配 `TreeItemMode::Tree`，文件目标回 400（`mono_api_service.rs:1310-1318`、`:1433-1445`）。用户选择**扩既有路径**，不新开 delete-file / move-file。
- **Decision:**
  1. 在 `DeleteEntryInfo` / `MoveEntryInfo` 增加 `is_directory: bool`，`#[serde(default = "default_is_directory")]`，`fn default_is_directory() -> bool { true }`。省略键 = 目录。JSON `null` 与其它非 `Option` bool（如 `skip_build`）一样走 extractor **422**。
  2. **类型澄清（相对核准草案的 `Option<bool>` + 裸 `#[serde(default)]`）：** 裸 default 作用在 `Option<bool>` 上得到的是 `None` 不是 `true`。本 ADR 用 `bool` + 具名 default 函数表达「省略 = 目录」，避免实现时踩空。
  3. `true`：只匹配 `TreeItemMode::Tree`（今日语义；Libra 目录 client 不用改字段）。目标是文件 → 400 `'…' is not a directory`。
  4. `false`：只匹配文件 mode（`Blob` / `BlobExecutable`）。目标是目录（或 `Link` / `Commit`）→ 400 `'…' is not a file`。
  5. **404 只在父 tree 里完全没有该 `name`。** 另一 mode 有同名项时走 item 3/4 的 400，不走 404。
  6. 禁止 Git `CommandType::Delete` 与 CL `build_signed_cl_update` / `apply_changes`（沿用 ADR-LB-02）。
  7. 落地仍走 `commit_tree_update` + `land_api_tip_push`；移档保留**同一 blob oid**（对齐全目录保留 tree oid）。
  8. 父目录被删/移空仍补 `.gitkeep`。ImportRepo 维持 409。
  9. 内容安全：一次操作一次 commit；不回收 blob / LFS / Media 物件（`DEFER-FT-01`）；确认对话由 client 做。
  10. `commit_msg`：按 `is_directory` 写 `delete/move/rename directory` 或 `delete/move/rename file`。
- **Alternatives considered:** 新 `delete-file` / `move-file` — 用户拒绝。`Option<bool>` 裸 default — 语义不是「默认 true」。按 Git delete command — 沿用 ADR-LB-02 拒绝。
- **Consequences:** 既有 `delete_entry_reject_file_400` 在省略字段时仍 400；FT-02 新增 `is_directory=false` 成功向量。不改 create-entry 字段。
- **Revisit when:** 需要 symlink / submodule 产品语义，或对象 GC。

### ADR-FT-02: GET list 的 query 形状；先改方法、再隔离

- **Status:** Accepted
- **Context:** POST JSON `PageParams{pagination, additional}` 无法原样放到 GET。60917 DEFER-LB-02 原文要「版本化 API + 双方法窗口」；用户明确选择 **GET-only**，POST 回 405。这是对 DEFER-LB-02 重启条件的**覆写**，必须在本 ADR 与 60917 DEFER 表（FT-09）登记。
- **Decision:**
  1. 唯一 list：`GET /api/v1/tags/list`。扁平 query **必填**三键：`page`、`per_page`、`path`（root 送 `path=/`；空白视同 `/`）。缺任一键、或 `per_page=abc` 这类反序列化失败 → axum 0.8 `Query` extractor **400** 纯文本、无 `CommonResult`（`FailedToDeserializeQueryString`；**不是**今日 POST JSON 缺键的 422）。
  2. 三键都在且为合法数字、但 `per_page=0` → handler 在调用 `get_tags_by_page` **之前**回 **400** + `CommonResult`，关掉 sea-orm `assert` panic。
  3. 成功仍是 200 + `CommonResult<TagListResponse>`。`page` 仍从 1 起。
  4. `POST /tags/list`：**405**。OpenAPI 三份锁、IT、`scripts/api_write_smoke_storage_only.sh`、`docs/monorepo.md` 全部改 GET。单元测试断言 POST 不再作为 `/tags/list` 的已登记方法。
  5. **顺序钉死：** FT-04 先改方法；list 过滤语意见面与今日相同（只有轻量按 path）。契约页隔离段标 `specified`，FT-06 再翻 `implemented`。不把 FT-04 挪到 FT-06 之后。
  6. **版本递增：** 删除公开 POST list 并改 query 形状属破坏性 HTTP 表面（ER-08）。FT-04 的 `Version increment` = **`minor`**。权威数字以该卡开工时 `Cargo.toml` 为准（成稿预期：FT-02/03 各 patch 之后为 `0.10.46` → `0.11.0`）。其后 FT-05/06/07 在 `0.11.x` 上 **patch**。
- **Alternatives considered:** 双方法窗口 / `/api/v2` — 用户拒绝。等 FT-06 再改 GET — 拒绝（用户选「先 GET、再 path 级」）。用 patch 夹带破坏性 list — 拒绝（ER-08）。
- **Consequences:** 破坏 Review / Libra 已 pin 的 POST list；`DEP-FT-01` outgoing。`PageParams<String>` 不再用于 tag list（其它调用方若仍用该 DTO 不受影响）。兼容窗口 = 无双方法；调用方必须在 `v0.11.0` 改 GET。
- **Revisit when:** 需要过滤/排序扩展或恢复 POST。

### ADR-FT-03: path 选择器 + 隔离（关 DEFER-LB-03 与 DEFER-LB-11 隔离面）

- **Status:** Accepted
- **Context:** get/delete handler 写死 `repo_path="/"`；服务层丢弃 path。`mega_tag` 无 path 栏。create 已把 tag 写到 `mega_refs.path = path_context`，但查找是全局的。
- **Decision:**
  1. Wire：`GET|DELETE /api/v1/tags/{name}?path=`。`path` 可选；省略或空 / 空白 = `/`。不改 URL 巢状，避免与 `{name}` 冲突。
  2. 查找键改为 **`(path, name)`**。不同 path 允许同名 tag。
  3. create 的重名检查改同一键（`path_context` 已存在；缺省 `/`）。
  4. delete 的 `trunk_write_requester` 改用**选择器 path**，不再固定 `/`。覆盖 `/project` 的 token 可删该 path 的 tag；删 root tag 仍需覆盖 `/`。
  5. list 的 `path` 对轻量与注解一视同仁（修 GAP-FT-04）。
  6. **迁移（FT-05，reader 之前）：** `mega_tag` 加 `path`（`TEXT NOT NULL`，default `/`）；以 `mega_refs.path` 按 `ref_name = 'refs/tags/' || tag_name` 回填，找不到则 `/`；加唯一约束 `(path, tag_name)`。`idx_mtag_tag_id` 保留。`down` 按本仓惯例可 no-op，`Rollback mode = forward-only`。
  7. storage API：注解 tag 新增/改 `get_tag_by_path_and_name`、`delete_tag_by_path_and_name`、`get_tags_by_page` 接受 path。轻量 ref **复用**已有 `get_ref_in_txn(path, ref_name)`（`mono_storage.rs:286-296`）；若产品路径不在事务内，加非事务包装，过滤条件与其相同，禁止再发明第三套 `(path, ref_name)` 查询。禁止继续用无 path 的 `get_tag_by_name` / `get_ref_by_name` 做 tag 产品路径（其它非 tag 调用方不在本卡改语义）。
  8. **仍延后：** 校验 `target` commit 是否属于该 path 子树（`DEFER-LB-11` 目标归属；本计划 `DEFER-FT-02`）。
- **Alternatives considered:** 巢状 `/tags/{path}/…` — 与 `{name}` 及 rooted path 冲突。只改 handler 不迁 `mega_tag` — 注解 tag 无法隔离。
- **Consequences:** FT-05 单独发布后、FT-06 之前：列上有 `path` 但查找仍全局——中间态可接受（create 仍全局拒重名，不会写出跨 path 同名）。FT-06 必须在 FT-05 之后。
- **Revisit when:** 需要 target 归属校验或跨 path 列举。
