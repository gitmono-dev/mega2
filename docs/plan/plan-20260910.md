# CL merge 强制走 MonoWriteQueue 并删除 legacy 写者计划（2026-09-10）

**模板版本：** v2；依据 [`plan-template.md`](plan-template.md)，核对日期 2026-09-10。

## 文档职责

本文解决「CL merge 仍可通过 `[monorepo].merge_writer = "legacy"`（及缺省 `legacy`）绕过 `MonoWriteQueue`，与 I5 / ADR-TP-05 的全序前提冲突」的缺口。前提是：**没有在跑老实例、不考虑存量 `merge_queue` 行迁移/吸收**。目标是交付：**全部 CL merge 入口只经 `MonoWriteQueue`（`kind=merge` → B3）；删除 `merge_writer` 配置与 Legacy processor；删除 `merge_queue` 表及 Rust 四层；保留 `/merge-queue` HTTP 形状作为 `push_queue` 的产品门面**。

本文只规划任务，不宣称实现完成。落地时每个任务都必须先刷新源码锚点（GC-01），再按任务卡验收。

### 适用范围

- CL merge 入口：`POST /cl/{link}/merge`、`POST /cl/{link}/merge-no-auth`、`POST /merge-queue/add` / `retry`。
- `/merge-queue` 的 list/status/stats 读路径（映射到 `push_queue` Merge 行）。
- `[monorepo].merge_writer` 配置、reload、样例与校验。
- Legacy 后台 processor（`ensure_merge_processor_running` / `execute_merge_workflow` / `merge_cl_unchecked`）。
- `merge_queue` 实体、storage/service/DTO、吸收路径、Postgres 表与相关枚举。
- UN-20 / UN-25 测试改挂 `push_queue`；部署与错误文档同步。

### 非目标

- **不删除** `/merge-queue/*` HTTP 表面（ADR-MW-02 / ADR-TP-05：保留路由与请求/响应形状）。`DELETE /remove` 与 `POST /cancel-all` 已 410，保持。
- **不做** 存量 `merge_queue` 行吸收（`prepare_for_queue_writer` / `absorb_into_push_queue` 删除，不迁移数据）。无老实例 ⇒ 表视为空或可丢弃。
- **不改** B3 merge 语义、UN-17 执行主体、UN-19 ACL、GPG 门、CL `revision` CAS。
- **不改** `push_policy` / trunk 直推 / attach / 物化路径。
- **不重开** DEFER-TP-01..05。
- **不回改** `plan-20260905` TP-07 历史验收勾选；本计划 **sunset** 该卡留下的开关与 dual-path。

### 成功定义

- 省略或写入任何历史 `merge_writer` 值后：不存在可编译/可运行的 Legacy merge 写者；CL merge 只走 `merge_cl_via_queue` → B3。
- `[monorepo]` 无 `merge_writer` 键；样例配置中的该行与注释消失；残留键按未知字段拒绝启动。
- `merge_queue` 表不存在；`src/` 无 `MergeQueueStorage` / `MergeQueueService` / `callisto::merge_queue`。
- `/merge-queue` 门面仍可用，读写均以 `push_queue` 为事实源。
- 全部非延后任务卡 `Lifecycle=done` 且 `Acceptance=complete`；计划级 Codex 评审对本计划文档 PASS。

## 已决议设计决策

### ADR-MW-01: CL merge 唯一写者是 MonoWriteQueue

- **Status:** Accepted
- **Context:** TP-07 用 `merge_writer` 做滚动开关；缺省 `legacy` 使未改配置的实例仍走 `merge_cl_unchecked`。用户确认无老实例、不做迁移。
- **Decision:** 删除 dual-path。所有 merge 入口只调用已存在的 `merge_cl_via_queue`（B1 入队 + 同步等 B3）。不保留「忽略配置但仍编译 Legacy」的中间态作为发布终态（MW-01 收口入口后，后续卡删除 processor/配置/表）。
- **Alternatives considered:** (1) 只改缺省为 `queue` 保留枚举——拒绝，旁路仍可启用；(2) 继续吸收存量行——拒绝，本计划前提是无迁移。
- **Consequences:** 省略配置即走 Queue；`/merge-queue/add` 对所有部署均为同步「已执行」。Review 形态也 spawn write-audit（队列成为 merge 的唯一根写者）。
- **Revisit when:** 若出现必须离线 merge 的紧急回退需求（预期永不）。

### ADR-MW-02: 保留 `/merge-queue` HTTP 门面

- **Status:** Accepted
- **Context:** ADR-TP-05 / trunk-push.md 明确 HTTP 表面保留指路由与 JSON 形状；执行已同步化。
- **Decision:** 不删除 `merge_queue_router`。list/status/stats/add/retry 只谈 `push_queue`。`remove`/`cancel-all` 保持 410。
- **Alternatives considered:** 删除 `/merge-queue` 只留 `/push-queue`——拒绝，属公开 API 删除，需独立 G-08 家族与客户端窗口（DEFER-MW-01）。
- **Consequences:** `QueueItem::from_push_queue` 与 `list_merge_for_legacy_ui` 名称可保留（非本计划改名轴）。
- **Revisit when:** 客户端全部改读 `/push-queue`。

### ADR-MW-03: 删除 `[monorepo].merge_writer`

- **Status:** Accepted
- **Context:** 开关只服务迁移；无实例后配置是谎言。
- **Decision:** 删除字段、枚举、reload 项、known-keys。样例与 `docs/deploy-trunk.md` 去掉该键。残留 `merge_writer = ...` 走既有未知字段拒绝（fail-closed）。
- **Alternatives considered:** 保留键但忽略——拒绝，GC-02 禁止死配置。
- **Consequences:** 运维必须从 toml 删行；MW-03 为公开配置面删除，`Version increment=minor`。
- **Revisit when:** N/A。

### ADR-MW-04: 不吸收，直接 DROP `merge_queue`

- **Status:** Accepted
- **Context:** 吸收是滚动部署产物；无老实例则 `Waiting/Testing/Merging` 行不是约束。
- **Decision:** 删除 `prepare_for_queue_writer` / `absorb_into_push_queue`。MW-05 以 forward-only 迁移 `DROP TABLE merge_queue`；若 Postgres 枚举 `queue_status_enum` / `queue_failure_type_enum` 无其它表使用则一并 `DROP TYPE`。不写 down。
- **Alternatives considered:** 保留空表——拒绝，双实体持续迷惑。
- **Consequences:** 若有人违反前提留下行，数据丢失且无补偿；本计划视为操作责任。UN-25 测试改挂 `push_queue`。日志事件名 **保持** `merge_queue_authz_frozen`（避免告警查询断裂；DEFER-MW-02 可改名）。
- **Revisit when:** 发现非空表的意外部署。
