# storage-only OCI Distribution 容器镜像仓库计划（2026-09-02）

**模板版本：** v2；依据 [`plan-template.md`](plan-template.md)，核对日期 2026-09-10。

## 文档职责

本文解决「monoengine 在 storage-only 形态下无法承载 OCI Distribution 协议（容器镜像 push/pull）」的缺口。目标是交付：**仅在 `git.storage_only()`（`push_auth` 显式配置）且 `[oci].enabled=true` 时挂载 `/v2` 协议面**——最小 push/pull 端点集（`/v2/`、manifests GET/HEAD/PUT/DELETE、blobs GET/HEAD/DELETE、blobs/uploads 全状态机、tags/list），认证复用 git 面（匿名读由 `git.anonymous_access`、写由 `git.push_auth`/`[[git.push_tokens]]` 决定；docker 客户端走 Basic 静态凭据流），元数据落 DB（4 张新表）、字节落对象存储（新增 `oci` 命名空间）。review 形态不注册任何 `/v2` 路由（fail-closed）。

参照实现分析基于 `/run/media/genedna/data/tmp/` 下的三个 pinned checkout：docker/distribution（规范基准）、rk8s `project/distribution`（Rust+axum 同构实现，主要移植蓝本，其 `/v2/{*tail}` 派发器是路由形态基准）、spegel（最小只读面）。kraken/harbor/quay/dragonfly 仅作概念参照（不 pin、不移植）。

本文只规划任务，不宣称实现完成。落地时每个任务都必须先刷新源码锚点（GC-01），再按任务卡验收。

### 适用范围

- `src/config/`：新增 `[oci]` 段（`enabled` 布尔）、`known_fields`、storage-only 校验门。
- `src/callisto/` + `src/jupiter/migration/`：4 张新表（`oci_manifest` / `oci_tag` / `oci_blob_ref` / `oci_upload`）与实体、迁移注册。
- `src/jupiter/storage/` + `src/jupiter/service/`：`OciDbStorage` + `OciService`（DB 元数据 + 对象存储字节）。
- `src/orbit_api/object_storage.rs`：`ObjectNamespace::Oci` 附录式新增。
- `src/ceres/oci/`（新目录）：OCI 错误封套、认证助手（Basic/Bearer 静态凭据流、registry ping 策略）、digest 工具、manifest 领域模型。
- `src/api/router/oci_router.rs`（新，`/v2/{*tail}` 单 catch-all + 路径派发器）+ `src/server/http_server.rs` + `src/api/api_doc.rs`：路由、挂载、OpenAPI。
- `tests/integration_oci.rs`（新）：进程级黑盒 IT；`scripts/oci_smoke_storage_only.sh`（新）：docker CLI live smoke。
- 文档：`docs/refactoring/oci.md`（新）、`docs/refactoring/orbit.md`（命名空间清单）、`docs/deploy-trunk.md`、`docs/refactoring/integration.md`、`docs/plan/README.md`、`plan-long.md` 索引。

### 非目标

- **不在 review 形态**（无 `git.push_auth`）挂载 `/v2`；`[oci].enabled=true` 且非 storage-only 时启动校验直接拒绝（ADR-DR-01）。
- **不实现** `_catalog`、referrers API、token 颁发服务（`/v2/auth`）、跨仓 GC、pull-through 代理/P2P（DEFER-DR-01..04）；blob/manifest `DELETE` 只注册路由并返回 `UNSUPPORTED`（不实现删除语义）。
- **不实现** 独立 OCI token 体系；无 OCI 专用凭据配置（ADR-DR-02）。
- **不支持** sha256 以外的 digest 算法（ADR-DR-05）；不做 manifest list 平台重写（docker ≥1.13 不需要）。
- **不修改** docker-compose-storage-only.yml（本计划 smoke 脚本独立运行，不新增 compose profile）。
- **不触碰** Git smart protocol / LFS 既有实现语义（只新增挂载点，不改变 catch-all 行为）。

### 成功定义

- storage-only + `[oci].enabled=true`：`docker login`（Basic 静态凭据）+ `docker push registry:9000/<repo>:<tag>` + `docker pull`（含多段 repo 名、分层并行拉取、chunked 上传、digest 校验）端到端可用；`anonymous_access=true` 时匿名 `docker pull` 无需凭据（含 registry ping 放行）。
- 认证矩阵生效：`push_auth=token` 时未认证写 401（`WWW-Authenticate: Basic` 挑战 + `UNAUTHORIZED` 封套）、有效 token 不覆盖 repo → `DENIED` 403；`push_auth=none` 时全放行；读侧完全跟随 `git.anonymous_access`。
- review 形态或 `enabled=false`：`/v2/*` 全部 404（不注册），OpenAPI 不含 `/v2` 路径。
- 上传会话跨重启可续（DB 行含 offset/chunks + 分片对象持久）；digest 校验失败保留会话；CAS 键只在 digest 验证通过后写入（两遍流式）。
- 全部非延后任务卡 `Lifecycle=done` 且 `Acceptance=complete`；计划级 Codex 评审对本计划文档 PASS。

## 已决议设计决策

实现时若需偏离本节，必须先修改计划并说明原因，不得在代码中静默改语义。

### ADR-DR-01: `/v2` 双重门——显式 `[oci].enabled` + storage-only

- **Status:** Accepted
- **Context:** 需求「只在 storage-only 模式下执行」。`storage_only()` 是 `push_auth.is_some()` 的推导；仅凭推导无法显式声明意图，也无法 fail-closed 拒绝错误部署。
- **Decision:** 新增 `[oci]` 段，仅一个字段 `enabled`（serde 缺省 `false`）。`app()` 挂载条件为 `config.git.storage_only() && config.oci.enabled`。校验：`oci.enabled=true` 且非 storage-only → 启动拒绝；storage-only 且 `enabled` 缺省 → 不挂载（非错误，日志提示）。
- **Alternatives considered:** (1) 纯推导（storage-only 恒开）——拒绝：无法按实例关闭，违反最小暴露；(2) 独立 token——拒绝：与 git 面双轨。
- **Consequences:** 部署者需在 config-storage-only.toml 显式加 `[oci] enabled = true` 才启用；`/v2` 默认 404。
- **Revisit when:** 若 trunk 形态需要镜像分发（需重新评审认证与配额）。

### ADR-DR-02: 静态 Basic 凭据流，复用 push token；registry ping 跟随匿名读策略

- **Status:** Accepted
- **Context:** docker 客户端对带 token 服务（realm/token URL）的 Bearer 流需要额外服务端组件；纯 Basic 挑战（`WWW-Authenticate: Basic realm=...`）docker 原生支持：`docker login` 先 GET `/v2/` 验证凭据（200 = 有效、401 = 无效），此后所有请求带 `Authorization: Basic base64(user:password)`。storage-only 已有 push token 体系（`lookup_push_token` 常数时间比较）；为 OCI 再造 token 服务器违反 GC-02。匿名 `docker pull` 前同样会 ping `/v2/`，因此 ping 必须跟随读策略。
- **Decision:**
  - 凭据解析：`Authorization: Bearer <token>` 直取；`Authorization: Basic` 取 password 为 token（username 可为任意值，仅记日志），复用 git 面解析习惯（`git_protocol/http.rs` 既有实现或等价代码）。
  - 挑战：401 时发 `WWW-Authenticate: Basic realm="monoengine registry", Bearer realm="monoengine registry"`（与 git `auth_failed` 同风格）。
  - 读（GET/HEAD manifest/blob、tags/list、`GET /v2/` ping）：`anonymous_access=true` 且无凭据 → 放行；`anonymous_access=false` → 要求有效 push token；携带凭据但无效 → 401（含 ping，保证 `docker login` 失败可呈现）。
  - 写（POST/PATCH/PUT/DELETE）：`push_auth=token` → `lookup_push_token` + `token_covers_repo("/" + repo)`；token 有效但不覆盖 repo → `DENIED`（403）；`push_auth=none` → 全放行。
- **Alternatives considered:** 独立 token 服务器/Bearer realm——拒绝：新增组件与面；`silly` 式任意非空 Bearer——拒绝（无实际保护）；ping 恒 401——拒绝（阻断匿名 pull，R2 修正）。
- **Consequences:** `docker login <host> -u <任意> -p <push token>` 即完成认证；OCI 写权限粒度 = `token.paths` 前缀匹配（repo 当 `/repo`）。无 token 服务器、无 scope 协商。
- **Revisit when:** 需要细粒度仓库配额/租户或标准 Bearer token 流时。

### ADR-DR-03: 元数据 4 表 + 字节对象存储，无 link 文件

- **Status:** Accepted
- **Context:** docker/distribution 用存储驱动 link 文件表达 tag/manifest/blob 关系；S3 上 link 文件遍历昂贵且无事务。quay/harbor 证明 DB 元数据模型成熟。storage-only 形态本就有 Postgres（无内嵌 DB 模式）。
- **Decision:** 4 表：`oci_manifest(repo_name, digest, media_type, size, created_at)`、`oci_tag(repo_name, tag, digest, updated_at)`（复合 pk）、`oci_blob_ref(repo_name, digest, size, created_at)`（repo→blob 成员关系，供 manifest 校验与未来 GC）、`oci_upload(uuid pk, repo_name, offset, chunks, started_at, updated_at)`。字节全部在对象存储 `oci` 命名空间。无 `oci_repository` 表——repo 存在性 = 有 manifest/tag/blob_ref 行（`_catalog` 非目标）。
- **Alternatives considered:** link 文件布局——拒绝（S3 遍历/一致性差）；内存会话表——拒绝（跨重启不可续）。
- **Consequences:** manifest PUT 校验引用 blob 走 `oci_blob_ref` 点查；`NAME_UNKNOWN` 判定走 manifest 行存在性。
- **Revisit when:** 引入 `_catalog` 或配额时考虑 `oci_repository` 表。

### ADR-DR-04: 端点范围 = 最小 push/pull + tags/list；DELETE 注册但恒 `UNSUPPORTED`

- **Status:** Accepted
- **Context:** docker 客户端 push/pull 全流程只需：`/v2/`、manifest GET/HEAD/PUT、blob GET/HEAD、uploads 全状态机（含 mount、monolithic）、tags/list。
- **Decision:** 实现上述端点。manifest/blob `DELETE` 注册路由但恒返回 `UNSUPPORTED`（405 封套，与 distribution 默认 `delete.enabled=false` 行为一致；不注册会导致裸 404/405 而非 OCI 封套）。`_catalog`、referrers 不注册。`tags/list` 支持 `n`/`last` 分页与 `Link` 头。
- **Alternatives considered:** 完整 spec——拒绝：catalog/delete 与安全/GC 强耦合，超出本计划轴。
- **Consequences:** 依赖 catalog 的 UI/工具不可用（DEFER-DR-01）；docker/containerd/oras/crane 不受影响。
- **Revisit when:** 需要 registry UI 或回收能力时。

### ADR-DR-05: 仅 sha256；manifest 原样存回，不做平台重写

- **Status:** Accepted
- **Context:** docker 实际只发 sha256；4 种 manifest mediaType（Docker schema2 / manifest list v2 / OCI manifest / OCI index）需按原字节往返。
- **Decision:** digest 解析仅接受 `sha256:<hex64>`，其余 `DIGEST_INVALID`。manifest PUT 按 mediaType 白名单校验后原样入对象存储（key `manifests/sha256/<hex>`），GET 原样返回存储 mediaType。by-tag PUT 的 digest **由服务端对 body 计算**（manifest 自身无 digest 字段；仅 by-digest PUT 校验 URI digest 与计算值一致）。不重写 manifest list 平台（docker ≥1.13 发送 `Accept` 覆盖 list）。
- **Alternatives considered:** 完整 OCI spec crate（`oci-spec`）——拒绝：新依赖，本仓约束禁止无谓增依赖；sha512——拒绝：无客户端使用。
- **Consequences:** `docker pull` 旧客户端（<1.13）对多平台 list 可能取不到默认平台（极低风险，DEFER-DR-05）。
- **Revisit when:** 需要 schema1 兼容或平台重写时。

### ADR-DR-06: 上传会话 = DB 行（offset+chunks）+ 分片对象 keys；complete 两遍流式、CAS 键先验证后写入

- **Status:** Accepted
- **Context:** S3 无 append 语义；对象存储 trait 无 list/rename/copy 原语（`src/orbit_api/object_storage.rs:173-344`），分片寻址必须完全确定性；`put_stream` 落键必须在流开始前确定，而 CAS 键由 digest 决定、digest 只能在流式读完分片后得到——单遍写 CAS 键意味着未验证字节已污染内容寻址存储；distribution 的 HMAC `_state` 方案在有 DB 时冗余。
- **Decision:**
  - `POST` 建 `oci_upload` 行（uuid，offset=0，chunks=0）；每个 PATCH 写分片 `uploads/<uuid>/<seq>`（seq = 当前行 `chunks` 值），随后条件更新 `UPDATE ... SET offset=?, chunks=chunks+1 WHERE offset=<写入前值>`（冲突 → `RANGE_INVALID`，防并发 PATCH 交错）；`GET` 状态读 DB offset。
  - `PUT ?digest=` 完成走**两遍流式**：pass A 按 seq 0..chunks-1 顺序流式读分片仅做 sha256（不落任何 CAS 键）→ 与请求 digest 比对，不符 → `DIGEST_INVALID`（会话/分片保留）；pass B 再次流式读分片 → `put_stream(blobs/sha256/<actual>)`（键由已验证的 actual digest 决定）。两遍均常数内存；总成本 2 读 + 1 写 O(size)。
  - 成功 → 写 `oci_blob_ref`、按 seq 逐个删分片、删会话行；`DELETE` → 按 seq 逐个删分片 + 删行。跨重启可续（行与分片都持久）。
  - **崩溃窗口**：PATCH 写分片成功但 DB 未更新 → 孤儿分片（不可达、无害，GC 延后 DEFER-DR-03）；pass A 后崩溃 → 会话原样，重试无副作用；pass B 中途崩溃 → CAS 键存在部分字节但 `oci_blob_ref` 缺失（对读者不可见），重试 complete 覆写同键（内容寻址，覆写安全）。**不使用** `exists → skip` 快捷路径。
- **Alternatives considered:** HMAC `_state` URL token——拒绝（DB 已可校验会话归属）；object_store multipart API——拒绝（LocalFileSystem 后端不支持）；单遍流式写 CAS 键——拒绝（未验证字节污染 CAS，R2 修正）；staging 键 + 整对象 copy——拒绝（trait 无 copy 原语，且成本同为 2 读 1 写）。
- **Consequences:** complete 成本固定 2 读 + 1 写 O(size)；对 >1GiB 层可接受（见性能摘要）。
- **Revisit when:** S3 multipart/copy 可用且需省一趟读时。

### ADR-DR-07: `oci` 命名空间键布局

- **Status:** Accepted
- **Context:** 需与既有命名空间（`git`/`lfs`/...）互不干扰且可预测。
- **Decision:** 全部键以 namespace `oci` 前缀：
  - `blobs/sha256/<hex>`（CAS blob）
  - `manifests/sha256/<hex>`（原始 manifest JSON bytes）
  - `uploads/<uuid>/<seq>`（上传分片，seq 从 0 递增十进制，见 ADR-DR-06）
  `ObjectKey` 校验与 `default_sharding()` 沿用既有逻辑。
- **Alternatives considered:** distribution 三层 shard 路径——拒绝：本仓 `default_sharding` 已提供 sharding。
- **Consequences:** 键与 digest 一一对应；GC 时按前缀枚举即可。
- **Revisit when:** 引入多算法 digest。

### ADR-DR-08: `/v2` 路由 = 单 `/{*tail}` catch-all + 路径派发器

- **Status:** Accepted
- **Context:** OCI repo 名含 `/`（`team/image`），axum 的 `{name}` 单段参数无法匹配；rk8s 的 `create_v2_router` + `dispatch_handler` 用 `/{*tail}` 自解析（`api/v2.rs:20/55`）；monoengine git 协议本就是 catch-all 自解析（`parse_git_protocol_path`）。
- **Decision:** `/v2` 下注册单条 `/{*tail}` catch-all（base `/v2/` 用同路由空 tail 处理），handler 内自实现路径解析：按后缀分派 `blobs/uploads/<uuid>` → `blobs/<digest>` → `manifests/<reference>` → `tags/list`，`name` = 剩余前缀段（校验 name 正则，段内禁 `..`）。每个子 handler 返回 `OciError` 封套；未知形状 → `NAME_INVALID`/`BLOB_UPLOAD_UNKNOWN` 等对应码。
- **Alternatives considered:** `nest("/v2", Router::new().route("/{*name}/manifests/{ref}", ...))`——axum 0.8 `{*name}` 中间段捕获不支持多段+后缀组合的确定性分派（已知限制），且 `*` 通配只能出现在末尾；拒绝。
- **Consequences:** OpenAPI 无法自动生成细粒度路径（本计划以路径级文档 + 运行时聚合说明，见 DR-11）；所有 OCI 请求走同一 handler 入口（与 git 协议一致）。
- **Revisit when:** axum 支持中段通配或迁移到专用 registry 服务时。

## 全局工程约束

遵守模板 GC-01..GC-12；本 checkout 发布命令以 AGENTS.md 的 Libra 为准。本计划附加：

- **GC-DR-01:** `/v2` 只允许在 `storage_only() && oci.enabled` 时挂载；review 形态任何提交不得出现 `/v2` 路由。
- **GC-DR-02:** OCI 认证不得弱于 git 面：写侧必须经过 `apply_push_auth_gate` 等价语义（token 覆盖检查 / none 显式放行）；读侧（含 ping）必须跟随 `anonymous_access`；mount 必须同时要求目标写授权与源读授权。
- **GC-DR-03:** OCI 响应一律走 `OciError` 封套（`{"errors":[{code,message,...}]}`），禁止复用 `ApiError`/`CommonResult`（JSON 形状不符 docker 客户端解析）。
- **GC-DR-04:** 上传/下载字节流式处理（`put_stream`/`get_range_stream`），禁止把整层读入内存（GC-10）。
- **GC-DR-05:** 不新增 crate 级 `#[allow(...)]`；生产路径不新增裸 `unwrap`/`expect`。
- **GC-DR-06 命名测试门防幽灵:** 本计划所有**函数级**命名测试过滤门（`cargo test ... '<mod>::tests::<fn>'`）一律加 `--exact`，并以其输出**出现目标测试名且 `1 passed; 0 failed`** 为判定依据；cargo 对未匹配过滤器返回 0 属幽灵验收，判 FAIL。**模块级全量门**（`--lib '<mod>' -- --nocapture`）不是函数级过滤，不加 `--exact`，其覆盖以全量输出佐证。带多个测试名的过滤（前缀过滤除外）按多个独立门计数。
