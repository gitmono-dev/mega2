## 文档职责

本文规划运维静态配置的 storage-only outbound webhook：在服务端确认业务写入提交后，尝试发送一份有界、仅含元数据、带 HMAC 的通知。它是 committed-write emitter，不是可靠消息平台。本文仅规划，不宣称实现、测试或发布完成。

初稿授权写集只有 `docs/plan/plan-20260912.md`，使用 apply_patch 创建和修订，执行真实 codex CLI 计划审查。用户要求主 Agent 在实际 Codex 计划审查 PASS 后，仅提交本计划文件，不递增版本，不推送。委派指令中的“Do not commit”只限制受委派 Agent 自行提交，不撤销主 Agent 的提交授权，也不是用户新增的禁止提交指令。受委派 Agent 完成修订与审查后交回主 Agent，由主 Agent 使用 Libra 精确提交本文件；初稿不套用实现卡的自动 bump/push 规则。

### 适用范围

- `git.storage_only()` 下 `push_auth=token` 与 `push_auth=none` 都可启用静态 emitter。
- Git 实际 B3 push 落地（含产品 API 写）、OCI manifest publication、LFS basic 实际上传、FastCDC media finalize 的可观测提交点。
- Agent Capture 落地后只增加 `agent_capture.events.committed`、`agent_capture.checkpoint.committed` 两种适配器。
- 配置校验、SecretRef 解析、进程资源生命周期、每卡测试与中文文档；没有 webhook DB schema 变化。

### 非目标

- 永久排除本计划：webhook CRUD、入站 webhook、outbox、持久 delivery 状态、retry worker、消息补发、消费确认协议。
- 保留现有 review CL webhook，不删除、不重用其数据库订阅、重试或 delivery 表；不改变既有 notification webhook。
- 不承诺 exactly-once、有序或 durability；不声称所有 2xx、所有对象 PUT 或所有 Git `Done` 都代表新的业务提交。
- 不改变 Git/LFS/OCI/Agent Capture 入站认证；不为 media 凭空制造 actor，不为未知 LFS 上传猜测仓库归属。
- 不将 presigned PUT 发放认作上传提交，也不新增对象存储回调、轮询或 verify API。

### 成功定义

- 被选中的已提交写入可触发一次非阻塞投递尝试；饱和、关闭、网络失败不会改变写入结果。
- 出站接收者只能看到静态过滤允许的元数据，接收方可以验证原始请求体的 HMAC。
- 每张卡有独立测试、文档、review、版本与发布证据；所有非延后卡最终 `done / complete` 才能称计划完成。
- WH-01..WH-13 已交付并发布。Agent checkpoint 事件由 WH-08 支持。追加的 WH-14/WH-15 补齐配置字段约束与 emitter 记录/记账契约。

## 已决议设计决策

### 实现接口契约（开工前冻结）

以下是 WH-01/09/12/10/02/11 之间的最小接口契约。实现可以使用等价的内部命名，但不得改变字段语义、可见性或错误边界；来源 adapter 只能调用 `try_emit`，不能直接调用 transport。

```rust
struct CommittedEvent {
    event_id: EventId,
    event_type: EventType,
    occurred_at: DateTime<Utc>,
    source: EventSource,
    scope: EventScope,
    data: EventData,
}

struct EventTarget { /* immutable compiled config and resolved SecretString */ }

trait EventTransport: Send + Sync {
    fn post(&self, target: &EventTarget, body: Bytes) -> TransportFuture;
}

impl StorageEventEmitter {
    fn try_emit(&self, event: CommittedEvent) -> AdmissionDisposition;
    async fn shutdown(&self);
}
```

`CommittedEvent` 在 WH-10 构造并序列化为一次不可变 body；WH-10 负责白名单、scope、过滤和 16 KiB 限制，WH-09/12 负责单次安全 POST，WH-02 只负责 target fan-out、admission、reaping 与 shutdown，WH-11 负责将已解析 secret 绑定到唯一应用 owner。emitter 不访问 DB、对象存储或可变 latest 状态。`TransportFuture` 只接收已编译 target 与原始 body bytes；生产实现不得暴露私网映射开关，测试实现通过注入 transport 提供。

`TransportFuture` 的输出为 `Result<TransportSuccess, TransportError>`，只携带 2xx/非 2xx、连接、TLS、解析、超时或取消类别，不携带 response body。唯一同步返回类型为 `AdmissionDisposition`：`accepted { accepted_targets, dropped_targets }`、`dropped_disabled`、`dropped_invalid_scope`、`dropped_filter`、`dropped_size`、`dropped_capacity` 或 `dropped_closed`；已关闭 admission 为 `dropped_closed`，部分 target 取得 permit 时仍返回 `accepted` 并填写两项计数。它不返回异步传输结果；每个 target 独立记录 `DeliveryOutcome`，所有计数仅供日志/metrics 使用。

正常 HTTP、startup error、server error 与 Ctrl+C 路径必须显式调用 `shutdown().await`；调用可重复且并发安全，首个调用者只负责触发共享的后台 drain state，不持有唯一 future，调用者被取消后由 state 继续 drain，后续调用等待同一完成结果。同步 `Drop` 区分 clone handle 与 final owner：clone drop 不关停；final owner drop 关闭 admission、abort 全部未完成任务并释放资源，但不能同步 join。WH-02 交付此运行时契约，WH-13 负责 CLI 信号及 service/HTTP 外层显式清理，WH-11 在其发布后启用真实 secret。AppContext 构造内部若在 owner 创建后失败，由 WH-11 在返回错误前清理；构造成功后的全部退出由 WH-13 覆盖。测试必须覆盖正常 shutdown、error、Drop fallback、重复/并发 shutdown 与发起者 cancellation。

### 事件身份与 scope 不变量

- 每个 committed snapshot 只生成一次 `event_id`；同一次事件 fan-out 到多个 target 使用相同 ID。
- B3 使用稳定安装标识 `installation_id`（启动配置生成并持久保存于部署配置，长度 1..64 的 ASCII opaque 值）与 `sha256("repo.push\0" + installation_id + "\0" + canonical_repo_path + "\0" + operation_id + "\0" + landed_commit_id)` 的前 16 字节，以 UUID v5 字节布局编码为小写标准 UUID；queue 的 i64 id 不参与身份。接收方以已认证 target/installation 边界加 event_id 去重；安装标识变更即形成新的身份命名空间。OCI、LFS basic、FastCDC 与 Agent 的每次新业务提交使用 UUID v4，并将 installation_id 作为 UUID v4 的命名空间记录字段而不进入 wire envelope。
- `event_id` 测试覆盖同安装同输入稳定性、跨安装/ repo/operation/landed commit 区分；接收方不得依赖其跨进程持久存在，服务端也不维护 replay 状态。
- Git `scope` 只填 canonical `repo_path`；OCI 只填 `oci_repository`；LFS basic 三个 scope 值均为 null；media 只填服务端 `MediaScope` 提供的 canonical `repo_path`；Agent 同时填可信 `tenant_id` 与 `repo_path`。同一 envelope 不得同时填 `repo_path` 与 `oci_repository`，也不得用 null scope 绕过已配置过滤。
- `EventType`、`EventSource`、`EventScope`、`EventData` 为封闭内部类型；未知字段不能从调用方扩展到 JSON envelope。

### 固定 wire schema

`schema_version` 固定为整数 `1`；`event_id` 为 UUID 字符串；`occurred_at` 是 UTC Unix epoch seconds 的 u64 整数，取可信提交成功时刻；`source` 只允许 `git`、`oci`、`lfs`、`agent_capture`。所有字符串字段为 UTF-8、非空且不超过 4096 bytes；size/count/generation 为 u64 JSON integer，范围 `0..=u64::MAX`；`raw_committed` 为布尔值。`reference`、`stream_kind`、`completeness` 均为非空字符串，其中 `stream_kind` 允许 `external_capture`、`internal_code` 或 DEP 明确登记的新 kind，`completeness` 允许 `empty`、`incomplete`、`complete`、`truncated`，`transfer` 只允许 `basic` 或 `fastcdc`。

| event_type | source | scope | data 字段 |
|---|---|---|---|
| `repo.push` | `git` | `tenant_id=null`, `repo_path:string`, `oci_repository=null` | `push_id:string`, `operation_id:string`, `ref_name:string`, `old_oid:string`, `requested_oid:string`, `landed_oid:string` |
| `oci.manifest.published` | `oci` | `tenant_id=null`, `repo_path=null`, `oci_repository:string` | `digest:string`, `reference:string`, `media_type:string`, `size:u64` |
| `lfs.object.uploaded` | `lfs` | `tenant_id=null`, `repo_path=null`, `oci_repository=null` | `oid`, `size`, `transfer="basic"` |
| `lfs.media.finalized` | `lfs` | `tenant_id=null`, `repo_path:string`, `oci_repository=null` | `oid:string`, `size:u64`, `manifest_id:string`, `transfer="fastcdc"` |
| `agent_capture.events.committed` | `agent_capture` | `tenant_id:string`, `repo_path:string`, `oci_repository=null` | `capture_id:string`, `receipt_id:string`, `new_event_count:u64`, `stream_kind:string`, `generation:u64`, `completeness:string` |
| `agent_capture.checkpoint.committed` | `agent_capture` | `tenant_id:string`, `repo_path:string`, `oci_repository=null` | `capture_id:string`, `checkpoint_id:string`, `completeness:string`, `raw_committed:boolean` |

字段类型逐项固定：`push_id`、`capture_id`、`receipt_id`、`checkpoint_id`、`manifest_id`、`operation_id`、`ref_name`、所有 oid/digest/path/reference/media_type/stream_kind/completeness/transfer 均为非空 JSON string；`tenant_id` 非 null 时为非空 JSON string。`size`、`new_event_count`、`generation` 为非负 JSON integer，使用无损 u64 范围；`raw_committed` 为 JSON boolean。data 字段全部 required 且不可 null；scope 三个字段全部 required，严格按上表取 string 或 null。OID 为小写十六进制，path 为 canonical path，reference/media_type 不能为空。WH-10 的 `metadata_projection_budget` exact 测试覆盖六类 golden JSON 与类型、范围、格式、nullability 负例。

`AdmissionDisposition` 另有 `dropped_invalid_event`：scope 合法但 metadata 不满足上述类型、格式、范围、非空约束，或序列化失败时整事件丢弃，零发送；仅 scope 不合法时使用 `dropped_invalid_scope`。adapter 的 fallible builder 失败也记录 `dropped_invalid_event`，不得传播为业务失败。WH-02 的 `bounded_admission_and_reaping` 验证该结果及 partial/closed 分支。

每个 envelope 永远包含 `tenant_id`、`repo_path`、`oci_repository` 三个 scope keys；表中 null 表示该事件不具备该 scope，禁止省略。固定 envelope 为 `{"schema_version":1,"event_id":"<uuid>","event_type":"<literal>","occurred_at":<seconds>,"source":"<literal>","scope":{...},"data":{...}}`。scope 只允许表中组合；WH-10 为六种 event type 提供 golden JSON，并拒绝未知 source/type、错误 scope 与错误字段类型。

### 配置最小样例

WH-01 必须以如下结构为基准落地 parser、unknown-field 诊断和样例注释；数值仅展示字段位置和类型，默认仍为 disabled。`events` 必须非空，空过滤集合表示该来源不订阅；`/` 才表示该来源全树。

```toml
[storage_events]
enabled = false
installation_id = "prod-primary-01"
max_in_flight = 16
connect_timeout_seconds = 2
request_timeout_seconds = 5
shutdown_grace_seconds = 5

[[storage_events.targets]]
id = "ops-main"
url = "https://events.example.invalid/ingest"
secret_ref = "vault://secret/config/example/storage_events/targets/ops-main/hmac#value"
events = ["repo.push", "oci.manifest.published", "lfs.object.uploaded"]
git_paths = ["/team/a"]
oci_repositories = ["team/image"]
lfs_paths = []
include_unscoped_lfs = false
agent_tenants = []
agent_repo_paths = []
```

`max_in_flight`、timeout、grace 与 `installation_id` 是 `[storage_events]` 全局字段；`installation_id` 在启用时必填，由部署 provisioning owner 生成并持久写入受控配置，重启必须保持不变；每个 target 只有 `id`、`url`、`secret_ref`、`events` 及来源过滤字段。所有配置改变均 restart-required；disabled 时不解析 `secret_ref`。

字段约束固定为：`enabled` 默认 false；target 数量 0..16；`id` 为 1..32 个 ASCII 字符，仅 `[A-Za-z0-9_-]`，且不得重复；`events` 为 1..6 个不重复固定字面量；每个来源过滤集合 0..64 项，每项 1..256 bytes；`agent_tenants` 与 `agent_repo_paths` 必须同时为空或同时非空，非空时各自 1..64 项；`max_in_flight` 为 1..64，连接 timeout 为 1..5 秒，请求 timeout 为 1..10 秒，shutdown grace 为 0..10 秒。enabled=true 且 targets 为空是合法配置但无事件接收者；target 字段即使 disabled 也执行结构与 unknown-field 校验，但 disabled 时不解析 SecretRef、不执行连通性检查。WH-01/09/10 必须覆盖这些默认值、边界、重复 ID、空 targets 与 disabled 行为。

字段责任表：`enabled`、`targets`、target `id/events/filters` 由 WH-01 schema/unknown-field validator 校验；transport URL、timeout 与 HMAC 编码由 WH-09/12 校验；event/source/filter 组合、canonical path、collection 上限由 WH-10 校验。缺省 `targets` 与所有 filter 数组均为空；缺省 timeout 分别为 2/5/5 秒；target 的 `id`、`url`、`secret_ref`、`events` 在该 target 存在时必填。disabled 仍拒绝类型错误、未知字段、重复 id、非法 URL 形状和超限集合，但跳过 SecretRef 解析、DNS 解析与可用性检查。

enabled 时 `installation_id` 必须存在，disabled 时可省略；其值为 1..64 个 ASCII `[A-Za-z0-9_-]`，不得自动生成。重启稳定性与跨安装区分必须由 WH-01 测试验证。

### ADR-WH-01: 静态配置、双模式与隔离

- **Status:** Accepted
- **Context:** storage-only 已支持 token/none；不能依赖用户 CRUD 或旧 CL 订阅表。
- **Decision:** 新增 `[storage_events]`，默认 `enabled=false`；启用要求 `git.storage_only()`，对 token/none 同样有效。`[[storage_events.targets]]` 每项 `id`、`url`、`secret_ref`、显式非空 `events`，及 `git_paths`、`oci_repositories`、`lfs_paths`、`include_unscoped_lfs=false`、`agent_tenants`、`agent_repo_paths`。空过滤列表代表不订阅该来源，不是全局通配；Git/LFS/Agent 根路径 `/` 才显式表示全树，OCI 使用规范 repo 名精确匹配；Agent 必须同时配置非空 tenant 精确集合与 repo 路径集合。各来源按自身维度匹配，不能拿 Git 路径替代 OCI repo 或 tenant。id 仅允许短 ASCII 标识符，禁止重名。
- **Decision:** Git/LFS/Agent filter与可信scope均要求绝对 canonical path：仅 `/` 可尾随斜线；拒绝空值、反斜线、重复分隔符、`.`/`..`组件、控制字符、query/fragment、百分号编码及前后空白，不做宽松解码/替换。路径按已验证规范形式原样匹配，`p==f` 或 `p.starts_with(f + "/")`；`/team/a`匹配自身与`/team/a/b`，不匹配`/team/ab`。事件路径不符合规范则丢弃，不能降为unscoped来绕过过滤。OCI repo按现有valid_repository_name规则校验后大小写敏感精确匹配，不给隐式前缀；tenant按服务器值大小写敏感精确匹配。
  `/` 是唯一例外：通过 canonical validation 后匹配所有合法路径；非根过滤才使用 `p==f || p.starts_with(f + "/")`。测试必须覆盖根、自身、后代、前缀碰撞与非法路径。
- **Alternatives considered:** DB CRUD/outbox 与本范围不符；只支持 token 会错误排除 none。
- **Consequences:** 配置全部 restart-required。WH-01先发布配置装载/形态门，WH-09完善运输参数校验，WH-12完善DNS地址策略，WH-10完善事件/过滤参数校验；直到WH-11才把真实transport启用到应用。各中间切片默认disabled且无生产源hook，文档标为准备接口，不能声称enabled已有投递能力。WH-02只提供可注入、默认disabled的运行时。来源适配从WH-03开始。
- **Revisit when:** 需要动态管理订阅或可靠 delivery，另立计划。

### ADR-WH-02: 元数据与 HMAC 网络边界

- **Status:** Accepted
- **Context:** 出站是数据披露；write auth 与发送认证是两个边界。
- **Decision:** 目标仅 HTTPS，无 userinfo/query/fragment；URL 为运维可信非 secret，禁止把凭证嵌 URL。HMAC secret 必须为 `SecretRef`，命名空间 `vault://secret/config/<profile>/storage_events/targets/<id>/hmac#<field>`，启用时启动解析失败则服务启动失败，disabled 不解析。解析后的 key 必须是非空 UTF-8 secret，解码后长度 32..=256 bytes；本版只接受带前缀的 `hex:<even-hex>` 编码，禁止 base64url，避免编码歧义；空值、奇数 hex、非法字符、解码后短于32 bytes均在启动时拒绝。复用 SecretString，不将解密值写回 config snapshot。禁止 redirect，禁用环境代理；仅允许公共地址，连接必须使用同次解析且校验过的 IP（保留原 hostname 的 TLS/SNI），拒绝任何私网/loopback/link-local/metadata 地址及混合解析结果，防 DNS 重绑定；测试用私有 transport 注入，生产不提供 HTTP/私网逃逸开关。
- **Decision:** JSON envelope 固定白名单 `schema_version=1,event_id,event_type,occurred_at,source,scope,data`。scope 为 `tenant_id,repo_path,oci_repository`，未知值 null；不填虚假 actor，本版统一不发 actor。签名头 `X-Mega2-Event-Id`、`X-Mega2-Timestamp`、`X-Mega2-Signature: sha256=<hex>`；HMAC-SHA256 输入为 timestamp 的十进制秒、`.`、实际发送 body bytes。接收方按 ±300 秒及 event_id 缓存做本地 replay 防护；这不是服务端 exactly-once。相同 emitter 事件 fan-out 保留 event_id。
- **Alternatives considered:** 直接序列化实体/请求会泄漏；签 URL 或复用 push token 混淆权限。
- **Consequences:** 禁止 raw、prompt、tool payload、token、对象键、URL、任意客户端扩展字段；日志仅 target id/event type/结果类别/计数，无请求响应体、URL 或 reqwest 原始错误。HMAC 与 JSON golden 向量同卡测试。
- **Revisit when:** 有可信内网目的地需求，另行网络策略 ADR。

### ADR-WH-03: 有界 best-effort 与 shutdown

- **Status:** Accepted
- **Context:** `spawn` 内 await semaphore 会累积无界等待任务；只丢 JoinHandle 不能保证释放。
- **Decision:** 配置上限 targets≤16，每 target 每来源 filters≤64、单项≤256 bytes，event payload≤16KiB（硬上限，超限整事件丢弃，不悄悄截断），max_in_flight 默认16、范围1..64；connect timeout默认2秒、范围1..5；总 request timeout默认5秒、范围1..10；shutdown grace默认5秒、范围0..10。启动编译过滤器，调用端只作有界匹配与元数据复制。对每个匹配 target 在 spawn **前** `try_acquire_owned`，拿不到立即记 dropped_capacity；无排队、无等待 permit 的任务、无背景 DB/对象读取。
- **Decision:** 一个请求只发送一次，不重试（含 429/5xx）；仅 2xx 算送达，不读无界响应体。transport 整段 DNS/连接/发送都纳入总 timeout。任务 owner 在 AppContext/Storage 生命周期唯一，共享 handle 可 clone；shutdown 原子关闭 admission，等待已接纳任务至 grace，超时 abort 并 join，处理 startup error、server error、正常 Ctrl+C 与 drop。已完成任务记录及时回收，不能让 JoinHandle 集合随事件总量增长。关闭与 spawn 登记须同步，关停后不得漏登记任务。
- **Alternatives considered:** outbox/retry、无限队列或 detached tasks 不符合范围。
- **Consequences:** 每进程内存 O(target/filter 配置 + max_in_flight × 16KiB)，按每个 target 计 permit。饱和可能导致部分 fan-out 投递；进程在业务 commit 后/try_emit 前崩溃会丢事件；远端已接收但客户端超时也无法确认。无 exactly-once、顺序、durability。多个服务进程分别有容量上限。
- **Revisit when:** 业务要求补偿或重放。

### ADR-WH-04: 提交点与不可变事件快照

- **Status:** Accepted
- **Context:** 网络请求成功、对象阶段完成和新业务提交不同。
- **Decision:** 使用内部 typed `CommittedEvent`；快照仅从本次操作的可信提交上下文构造，不在异步发送时查 latest。各适配器唯一语义如下。

| event_type | 提交点 / data 白名单 | 明确排除与重复语义 |
|---|---|---|
| `repo.push` | storage-only、真实 kind=Push、n>0 的 B3 txn.commit 成功后、C-segment 前；`push_id,operation_id,ref_name,old_oid,requested_oid,landed_oid` | 不在协议 handler/API caller 再发；old 是被接受路径前值，landed 是真实落地值；排除 N=0、Done replay、attach、merge、requeue、rollback、CAS/fencing 失败；不会逐个 descendant ref 发事件 |
| `oci.manifest.published` | 当前 put_manifest 的对象+manifest DB+可选 tag 写全成功；`digest,reference,media_type,size` | 不监听 chunk/blob/mount；tag 后续被改写不影响快照。每次成功发布请求可产生事件，重复 PUT 可重复通知；部分写成功后报错不发，不宣称跨资源原子性 |
| `lfs.object.uploaded` | basic 校验成功且本次实际 put_stream 成功；`oid,size,transfer="basic"` | batch 建行、exists no-op、hash/size失败不发。先 exists 再 put 存在竞态：并发上传可多次成功、多事件；不能称“首次写 exactly-once” |
| `lfs.media.finalized` | FastCDC finalized manifest 的本次实际 put 成功，fallback 已写入校验；`oid,size,manifest_id,transfer="fastcdc"` | prepare/chunk/fallback 中间步骤不发；已存在 finalized 的 no-op 不发。existing-check/put 非原子，跨进程重复可发生，不新增唯一性锁/表 |
| `agent_capture.events.committed` | DEP-WH-01 交付后，existing receipt/新 event rows 同一提交的返回快照；`capture_id,receipt_id,new_event_count,stream_kind,generation,completeness` | 每批每 stream/generation 一份摘要；只有新行数>0才发；receipt replay 或新幂等键携带全旧 uid 不发；不发事件原文或 UID 明细数组 |
| `agent_capture.checkpoint.committed` | DEP-WH-01 后 checkpoint 新提交快照；`capture_id,checkpoint_id,completeness,raw_committed` | raw_committed 只能取本次提交真实关联且已 committed raw blob 的事实；仅 redacted/incomplete 时 false；同 blob 新 checkpoint 可发，既有 checkpoint replay 不发 |

- **Alternatives considered:** 轮询已提交表无法在无状态模型内正确界定尝试；直接 hook object store 会逐 chunk、跨命名空间过发。
- **Consequences:** Agent batch 摘要只含有界 count，无 raw hash/key/URL；超16KiB丢整份。Git data 不含 commit message、作者、diff。业务成功后构造/投递失败只记 drop，不返回业务失败。
- **Revisit when:** 提交链或 snapshot 返回契约变化，先修计划。

### ADR-WH-05: LFS 覆盖边界与 Agent 前置

- **Status:** Accepted
- **Context:** basic 无可信 repo/actor，presigned 没回调；media HTTP依赖AccessTokenUser验证DB access token，LoginUser只是结果类型；Agent还没实现。
- **Decision:** basic scope 的 tenant/repo 为 null，只发给显式 `include_unscoped_lfs=true` 的目标；不能用曾经 batch 的 repo 推断全局 OID 的归属。media 从已验证 MediaScope 暴露只读 canonical repo getter，actor 不出站；不反解 scope digest。只观测现有可达 finalize，不改其认证。WH-06在storage-only的token/none两形态分别测试匿名、仅静态push token、有效DB access token三种请求：前两者不能当作AccessTokenUser凭据，后者按真实UserStorage与路由结果验收；DB token成立时可验证HTTP finalize正例。没有DB token时只断言原认证拒绝与零事件，不把service层hook测试冒充匿名或静态token HTTP贯通。
- **Decision:** presigned URL 发放与直传都不发事件，后续读到对象也不追溯补发；覆盖缺口列为 DEFER-WH-01。Agent 仅 WH-07/08 消费 AC-15 终态产物。完成后刷新 receipt/transaction/snapshot 真实签名，如需为 webhook 新增 schema 或先解决 Capture 自身事务错误，阻塞适配卡并交回 Capture owner，不能在 webhook 卡扩 schema。git.push_auth=none 不影响独立 ingest token 的认证与租户归属。
- **Alternatives considered:** 假 actor、推测 repo、以 raw_accepted 代替 raw_committed 都拒绝。
- **Consequences:** 本计划明确有传输覆盖缺口；不以虚构覆盖换取验收 PASS。
- **Revisit when:** media storage-only 认证或对象直传确认已有独立计划落地。

## 全局工程约束

- **GC-01 现状前置：** 每卡刷新锚点、配置、测试与脏状态；已经实现的部分改为同轴验证，不重复实现。
- **GC-02 单一事实源：** 配置、过滤、签名、运输只有一个实现，adapter 只消费可信 committed snapshot。
- **GC-03 移植边界：** 本能力为 mega2 扩展；无外部移植 pin，若改为移植须先登记 revision。
- **GC-04 错误契约：** 配置启动复用 MegaError，WH-01/09/10/11 同步 `docs/errors.md`；adapter 不改 HTTP/CLI 成功与错误映射。
- **GC-05 同卡文档：** 每卡实现+自身测试+中文 docs/README/config 注释在同一写集；索引在创建文档的卡完成。
- **GC-06 DB 验证：** DB 测试使用 `test_db_connection` 与 `apply_migrations(&db, true)`；没有新 webhook entity/storage schema，callisto/migration 同步 N/A，不能空建迁移。增加 integration target 同卡更新覆盖矩阵。
- **GC-07 安全边界：** 入站鉴权按实际现有链验证，不能依赖旧模板的 permit-all 快照。出站按 ADR-WH-01/02；静态过滤不替代入站授权。
- **GC-08 原子性：** 不扩业务事务、不回滚已提交写入；在事务内取得元数据快照，commit 后才能 try_emit。事件自身没有持久事务或补偿。
- **GC-09 资源：** 按 ADR-WH-03；环境测试用 `src/config/testing.rs` 的 env_lock/EnvVarGuard；不存在模板旧 `src/common/config` 路径。
- **GC-10 性能：** 无新增全表扫描、payload 读取或 N+1；过滤和容量均有硬上限。
- **GC-11 panic：** 不新增未解释 unwrap/expect/panic，不用 blanket allow 消警告。
- **GC-12 精确写集：** 只使用 Libra；每次状态与 diff 相对用户脏基线核对，仅 add 本卡文件。遇同文件用户改动不混提交。初稿由主 Agent 在实际 Codex PASS 后仅提交本文件，不 bump、不 push；受委派 Agent 只修订和审查，不自行提交。

